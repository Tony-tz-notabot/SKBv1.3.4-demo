# 判定与牌堆机制修订

## 一、牌堆初始化

对局开始前，服务器根据当前规则版本生成本局使用的完整牌组。

初始化流程为：

```text
读取规则版本对应的牌库配置
→ 创建每一张卡牌的独立实例
→ 将全部初始牌加入牌堆
→ 由服务器进行一次洗牌
→ 保存洗牌后的牌堆顺序
→ 向玩家公开牌堆数量
```

牌堆中的每张牌都具有独立的实例ID。

示例：

```json
{
  "instanceId": "card_0187",
  "templateId": "kill",
  "color": "BLUE",
  "zone": "DRAW_PILE"
}
```

玩家只能看到牌堆剩余数量，不能获得牌堆的具体顺序。

## 二、判定流程

进行判定时，不重新随机选择颜色或卡牌。

标准判定流程为：

```text
从牌堆顶部翻开第一张牌
→ 将该牌移动到中央区域
→ 公开牌名与颜色
→ 根据该牌的颜色及相关信息确定判定结果
→ 处理能够修改、替换或指定判定结果的效果
→ 结算判定对应效果
→ 将判定牌移入弃牌堆
```

因此：

> 判定结果取决于当前牌堆顶部的实际卡牌，而不是服务器临时随机生成一个颜色。

## 三、牌堆顺序

牌堆在对局开始前初始化并洗牌，此后牌序会因以下操作发生变化：

* 摸牌；
* 判定；
* 查看牌堆顶若干张牌；
* 调整牌堆顶顺序；
* 将牌置于牌堆顶；
* 将牌置于牌堆底；
* 从牌堆中搜索牌；
* 洗牌；
* 弃牌堆重新组成牌堆；
* 其他明确改变牌堆区域或顺序的效果。

普通判定只翻开当前最上方的一张，不额外洗牌。

## 四、牌堆耗尽

当需要摸牌或判定，而牌堆中没有牌时：

```text
将弃牌堆中的牌组成新的牌堆
→ 由服务器洗牌
→ 保存新的牌堆顺序
→ 从新牌堆顶部继续摸牌或判定
```

正在结算中的牌和其他区域中的牌不进入本次重洗，只有规则规定可以进入牌堆的弃牌堆卡牌参与。

如果弃牌堆也没有牌，则该次摸牌或判定无法翻开卡牌，并按照对应规则处理。

## 五、判定UI

判定开始时，中央区域播放真实的翻牌过程：

```text
牌堆顶部卡牌
→ 移动至中央区域
→ 翻至正面
→ 显示卡牌颜色和名称
```

中央区域只显示当前判定牌和简短状态，例如：

```text
正在判定……
```

翻开后显示：

```text
判定牌：蓝色【闪】
判定结果：蓝
```

结算完成后，判定牌从中央区域移动到弃牌堆。

详细过程进入日志：

```text
猎人弓进行判定。
从牌堆顶部翻开蓝色【闪】。
本次判定结果为蓝。
猎人弓获得对应效果。
判定牌进入弃牌堆。
```

## 六、修改判定与指定判定

能够干预判定的技能需要区分以下类型。

### 1. 翻开后修改判定

先正常从牌堆顶部翻开一张牌，再由效果改变其判定结果。

日志示例：

```text
从牌堆顶部翻开绿色【药水】。
原判定结果为绿。
受技能影响，本次判定结果修改为红。
判定牌仍为绿色【药水】。
```

此时需要区分：

* 实际翻开的卡牌；
* 卡牌的印刷颜色；
* 最终使用的判定结果。

### 2. 替换判定牌

若效果要求重新判定或替换判定牌，则：

```text
原判定牌按照规则进入对应区域
→ 再从当前牌堆顶部翻开一张牌
→ 使用新的判定牌进行结算
```

判定干预窗口为萨满专属：当且仅当有在场萨满时出现，仅萨满可见可操作；无萨满在场时判定直接结算，不出现窗口。萨满替换判定牌需弃置 2 张同色手牌，每个判定限 1 次替换；替换后重开窗口且只剩放弃选项。

不能在客户端直接生成一张不存在于牌堆中的判定牌。

### 3. 直接指定判定结果

例如萨满直接指定本次判定结果时，应按照具体技能规则处理。

如果技能规定“不进行普通判定，直接指定结果”，则：

* 不从牌堆顶部翻牌；
* 不消耗牌堆中的牌；
* 中央区域显示技能图像；
* 显示指定的判定结果；
* 日志说明本次判定由技能直接指定。

示例：

```text
萨满发动技能。
本次判定结果直接指定为红。
本次判定未翻开判定牌。
```

如果技能规定“翻牌后修改结果”，则仍然先从牌堆顶部翻牌。

具体采用哪种流程，由技能的正式规则文本决定。

## 七、服务端数据结构

对局状态必须保存完整牌堆顺序：

```json
{
  "drawPile": [
    "card_0187",
    "card_0042",
    "card_0211"
  ],
  "discardPile": [
    "card_0008",
    "card_0134"
  ]
}
```

数组第一项表示当前牌堆顶部。

判定命令不能包含客户端指定的颜色或卡牌：

```json
{
  "command": "START_JUDGMENT",
  "sourceEffectId": "effect_291"
}
```

服务器执行：

```text
取出 drawPile[0]
→ 从drawPile删除该实例
→ 生成判定翻牌事件
→ 结算判定
→ 将该实例加入discardPile
```

## 八、随机数的正确用途

服务器随机数用于：

* 对局开始前洗牌；
* 弃牌堆重洗；
* 随机选择角色；
* 明确写有“随机”的卡牌或技能；
* 超时情况下规则要求的随机选择。

服务器随机数不直接用于：

* 普通判定结果；
* 普通摸牌结果；
* 从牌堆顶部翻开的卡牌。

普通摸牌和判定都由已经确定的牌堆顺序决定。

## 九、事件记录

为了支持断线恢复和复盘，应记录：

```text
牌堆初始化完成
洗牌完成
牌堆版本更新
从牌堆顶部移出哪张牌
该牌因摸牌还是判定被移出
判定结果是否被修改
判定牌最终进入哪个区域
弃牌堆何时重新洗入牌堆
```

公开日志不能暴露尚未翻开的牌堆顺序。

服务端内部事件可以记录：

```json
{
  "eventType": "JUDGMENT_CARD_REVEALED",
  "cardInstanceId": "card_0187",
  "printedColor": "BLUE",
  "finalResult": "BLUE",
  "drawPileCountAfter": 183,
  "eventSeq": 482
}
```

## 十、最终规则表述

可在线上版规则中统一写为：

> 进行判定时，从当前牌堆顶部翻开第一张牌，以该牌的颜色作为本次判定结果。结算完成后，将该判定牌移入弃牌堆。若有技能或卡牌修改、替换或直接指定判定结果，则按照对应效果处理。普通判定本身不重新洗牌，也不单独生成随机结果。
