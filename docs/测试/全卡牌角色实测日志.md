## 第 1 局：knight / alchemist / headtaker / werewolf（gameId 50315186 / a2ea6b6d）

- **结果**：完整打完（A 队 seat1 骑士先被淘汰，随后一队全灭获胜）。**胜负未捕获**——测试期间为加"已结束房间可读"能力重启了服务器，内存房丢失。
- **覆盖机制**：骑士雕像（statue.knight 决斗：目标先手交替出杀→胜者武器攻击→结算，全流程正确）、炼金 toxic_reagent（弃绿牌对敌毒伤，狼人疑似毒免抵消）、枭首者 spartan_kick（弃牌阶段技能正常激活）、w61 扳手 weaponW61Choice（damage 路径自动攻击）、w57 `hp_at_least_2` 攻击模式（不耗杀）、special.sp10 奉献池（献祭武器，见下）、dying→淘汰、回合流转、B 队全灭胜负判定。
- **待确认**：special.sp10 用武器献祭时，驱动传的武器 ref 被拒 `WEAPON_NO_LONGER_LEGAL`（引擎对非法武器 ref 拒绝正确；疑为驱动陈旧 ref，非引擎 bug，需在真实客户端确认献祭 UI 的 ref 传递）。
- **协议注意**：`offer:statue-resolve:...:character:N` 虽把目标嵌在 offerId，引擎仍要求 selections.targets 提供目标（客户端经目标按钮正常发送）；程序化驱动必须带 targets。

## 第 5 局：assassin / wizard / qi_master / trap_master（gameId ff49301e，进行中因 bug 中断）

- **BUG-3（已修）**：`extraGemDeathTransfer`/`extraGemDyingResult`（额外宝石天赋·濒死交付手牌）在 app 层崩溃。濒死刺客 seat1 进入额外宝石交付窗口，选择交付对象后命令被拒，reasonCode 为原始 JS 错误 `"this.nextDeadlineAt is not a function"`。
  - **根因**：`windowRegistry` 的 `standard()` 工厂按 `(state, ruleset, deadline)` 构造，但 `ExtraGemDeathTransferSession` 构造函数是 `(state, nextDeadlineAt)`（第 2 参是期限函数而非 ruleset）→ `this.nextDeadlineAt` 被塞成 ruleset 对象，调用即 TypeError。
  - **修复**：`windowRegistry.ts` 改为自定义工厂 `new ExtraGemDeathTransferSession(s, d)`（d=期限函数）；新增 app 层测试 `windowCoverage.test.ts` 经 `GameService.handle` 复现并验证（接受、手牌交付正确）。全量测试 595 通过。
  - 其余 `standard()` 会话构造函数均为 `(state, ruleset[, deadline])` 或 `(state)`，无同类错配（已逐一核查）。
  - 本局其余覆盖：刺客、法师、气功、陷阱（未及打完整局，因该 bug 中断；修复后需重跑验证额外宝石流程）。

## 第 7 局：general / knight / paladin / ranger（gameId efa1370d，进行中疑似卡死）

- **BUG-4（已修）暗黑大骑士静滞单座卡死**：将军（seat1）装备并使用了暗黑大骑士 BOSS（`boss.dark_grand_knight`）后，round 2 将军出牌阶段**将军座位停止收到快照广播**（seat1 harness 停在 rev 114，其余 3 座到 rev 125）。
  - **根因**：非静滞/投影异常，而是 `buildDarkKnightActionOffers` 产出的 `kind:"createBlackSword"|"blackSwordAttack"` 不在协议 `InteractionOffer.kind` 枚举内 → 该座 GAME_SNAPSHOT 过不了客户端 Ajv 校验被拒收。窗口报价（windowOffer）kind 是固定映射、特殊出牌（physical/rangerRoll/assassinCreedDodge）只走响应窗口，均不受影响——因此仅将军座（出牌窗口优先座）卡住。
  - **修复**：schema 枚举补两 kind + 重生成 shared 类型 + 客户端标签「制造黑剑/黑剑攻击」；新增 `darkKnightStasis.test.ts`（3 项复现 + 25 角色出牌阶段投影扫描，全角色 offer kind 均在枚举内，证明无其他同类问题）。
  - **游戏内验证（round2 将军出牌阶段）**：四座同步到 rev 80（不再卡死）；「制造黑剑」执行成功（黑剑×1、HP 11→10）；「黑剑攻击」×3（刺/斩/锤）出现且可操作；其余角色/静滞态扫描无同类越界。
