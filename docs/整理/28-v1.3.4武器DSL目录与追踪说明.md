## 构建与校验

```powershell
node tools/build-weapon-rules.mjs
node tools/build-ruleset-data.mjs
node tools/validate-ruleset.mjs
```

校验器确认：

- 66个`weaponId`连续唯一；
- 颜色和数量与`cards.json`一致；
- 初始牌合计61；
- W001-W053无缺失和重复；
- 测试引用的武器模板全部存在；
- 简单武器必须恰有一个合法攻击模式，解析失败直接阻止构建。
- 判定武器必须有攻击模式、判定时间点、用途、作用域和完整结果；
- 判定结果可用`default`兜底，或完整覆盖白绿蓝橙红五色；
- 判定创建的伤害必须标记为附加伤害，替换基础伤害则不得标记为附加。
- 自动档射程必须严格递增，每档必须引用存在且射程一致的攻击模式；
- 自动档必须明确不可手选及射程0边界；
- 散弹和连击维度必须引用实际存在的伤害段，并分别绑定对应天赋来源。
- 蓄力档必须从0连续覆盖到最大值，并引用存在的攻击或非攻击结算模式；
- 蓄力生命周期必须明确提交清零、非装备区清零、装备转移/失效保留和借用蓄力0；
- 非攻击蓄力结算必须明确不创建攻击且不开放响应，其效果操作仍须通过DSL校验；
- 延时与转形效果必须使用登记操作，并明确目标复验、来源离场和禁止递归策略。
- 手选方式必须有默认方式、零费用切换和已提交攻击锁定；每个方式必须解析到实际攻击模式；
- 自动形态和自动血量档不得标记为玩家可选；
- 方式专属判定只能引用实际存在的攻击模式；
- 每回合尝试计数必须明确增加、重置及杀随后无效时是否回退。
- 特殊主动必须明确是否要求预选、费用、目标、超时和离场结果；
- 循环创建的弹头、群攻和瞄准攻击必须有显式上限或重入保护；
- 临时状态和临时资源必须有明确到期点、区域语义及清理操作；
- 全部武器完成后，W001-W053的`encodingStatus`必须统一为`effect_dsl_encoded`。
