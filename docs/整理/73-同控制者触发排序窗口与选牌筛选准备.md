# 同控制者触发排序窗口与选牌筛选准备

状态：排序窗口完成；通用触发选牌窗口进入下一实现项。

## 同控制者排序

- 同一事件、同一系统优先级、同一控制者存在多个触发时，事件桥不再只返回抽象停止原因，而是创建 `triggerOrdering` 权威窗口。
- 报价只发送给该控制者，候选项保存完整触发来源与原事件上下文；选择后重新校验触发仍成立，再原子关闭窗口并执行被选中的第一项。
- 命令校验游戏、修订、提示、优先权与报价，并以 `commandId` 幂等返回首次结果。
- 强制排序超时按全局规则从当前合法项中可复现随机选择，并写 `randomHistory`；不按代码注册顺序静默代选。
- 首项结算后，其 `trigger.resolved` 保存原事件键；事件桥再次运行时会跳过已处理项并继续剩余触发。

## 真实选牌触发筛选

- 三持的 `regularWeaponCountAboveCapacity` 已实现：仅统计三个常规武器槽；第三武器槽不计入；失去三持后超过基础容量2才匹配强制清理。
- 碎盾的 `causedByDamage` 与 `sourceHasDismantlableCard` 已实现：必须是伤害事实导致破盾，且伤害来源控制的生效装备区域仍存在可拆实例。
- 未知筛选仍失败关闭；本次没有放宽通用兜底。

## 下一边界

下一项先抽取事务内区域移动原语，再建立 `triggerCardSelection`：三持强制随机超时弃武器、碎盾可选拆牌及超时放弃都复用该窗口，并保留BOSS离场、装备失效和后续 `card.lost` 递归触发的原有语义。
