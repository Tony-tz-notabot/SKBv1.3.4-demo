# BOSS通用使用边界与首批生命周期

## 一、标准持续型BOSS使用

新增数据驱动的标准持续型BOSS使用事务与幂等命令：

- 仅自己的出牌阶段稳定窗口可从手牌使用；
- 每名玩家在当前全局回合最多成功使用一张BOSS，额度以`round:activeSeat`锚定，失败提交不消费；
- 普通持续型BOSS要求BOSS槽为空；仅死亡前的钢铁破浪者号可被新持续型BOSS替换；
- 替换旧牌进入弃牌堆与新牌进入BOSS槽属于同一原子事务；
- 即时响应型瓦尔基里与C6H8O6两种模式仍明确路由到后续专门流程，不被标准入口误用。

## 二、贡献追踪与清理

BOSS激活贡献按来源实例保存：铁盾增减、静滞、装备区失效来源、控制免疫来源及专属计数均有独立状态。自然到期时只移除当前BOSS实例的贡献，再将牌移入弃牌堆；不会误删其他来源的同类效果。

贡献清理已下沉到统一BOSS离槽原语，因此外部拆除、合法替换和自然到期使用同一路径。离槽同时取消该实例尚未创建的计划效果；已经进入攻击、伤害或触发结算的对象不依赖槽内牌继续存在，仍会完成。

## 三、首批时间点

- 紫爵士：使用回合结束阶段开始激活；下一个自己回合结束阶段开始前自然到期。
- 红爵士：相同激活点；激活时初始化`redLord.actualPositiveDamageCount=0`，第二个后续自己回合结束阶段开始前到期。
- 水晶巨蟹：使用回合结束时激活；两个后续自己回合开始各回复1点，第二个回合结束边界后到期。
- 大史莱姆：BOSS使用提交成功时立即标记激活；具体额外血量层仍属于下一步具体正文执行。

时间推进接口保持规则集可选参数以兼容纯时间轴单元测试；正式自动调度始终传入冻结规则集并执行BOSS时间点。

## 四、验证

已覆盖成功使用、同回合二次使用拒绝、普通槽阻挡、钢铁破浪者号替换及死后不可替换、报价过滤、命令幂等、紫/红/晶蟹/史莱姆首批时间点、自然到期及外部拆除贡献清理。服务端39个测试文件、178项测试和TypeScript构建全部通过。
