# 可复现随机、抽牌、弃牌与自动调度实现说明

本阶段把阶段正文第一版之后的七项基础工作收束为可供后续规则执行器复用的服务端边界。

## 已实现

- 权威状态持有可序列化的确定性随机源；初始洗牌、弃牌堆重洗和强制弃牌均可复现。
- `randomHistory`保存随机序号、用途、完整候选和结果；随机源同时进入引擎契约Schema。
- 抽牌原语支持一次抽取跨越牌堆耗尽边界：弃牌堆即时重洗后继续，其他区域不参与；双堆为空时实际摸牌数可少于请求数。
- 手牌上限统一为`max(0, min(4, 当前血量) + 修正)`；没有血条时当前血量按0参与计算。
- 弃牌阶段仅在超限时建立强制窗口，窗口携带精确弃牌数和当时的合法手牌引用；未超限直接完成正文。
- 手动阶段命令校验游戏、修订号、操作者、提示、报价和选择；重复命令返回同一结果，拒绝不改变权威状态。
- 强制弃牌超时从当前合法手牌中随机选择恰好所需数量，并记录随机历史。
- 自动调度器连续执行稳定的阶段正文与时间轴提交，遇到玩家窗口、判定/响应栈或对局结束即停止。最大连续步数读取`settings.engine.autoAdvanceMaxSteps`。

## 事件与原子性

重洗和跨重洗抽牌属于同一事务；`deck.exhausted`、`deck.reshuffled`和`card.drawn`具有同一状态修订。弃牌提交在单一事务中移动全部所选牌并关闭窗口。自动调度器由多个可审计的小事务串行组成，不把跨阶段历史压成一个不可恢复的大提交。
