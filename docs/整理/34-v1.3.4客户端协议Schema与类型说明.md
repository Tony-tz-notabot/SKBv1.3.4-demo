# v1.3.4 客户端协议Schema与类型说明

状态：对局内机器协议第一阶段已完成。

## 一、产物

- `protocol/v1.3.4/client-protocol.schema.json`：客户端对局协议单一数据形状来源；
- `tools/build-client-protocol.mjs`：无第三方依赖的TypeScript类型生成器；
- `shared/src/generated/client-protocol.ts`：生成的共享类型，禁止直接编辑；
- `tools/validate-client-protocol.mjs`：引用完整性、必需定义和生成一致性校验。
- `protocol/v1.3.4/examples/client-protocol.examples.json`：对局协议正反例；
- `tools/validate-protocol-examples.mjs`：结构、判别载荷和跨字段运行时验收。

当前Schema包含42个定义、75个内部引用，覆盖：

- 座位、队伍、阶段、对象引用、卡牌颜色和类别；
- 卡面、玩家、公开视图、个人视图；
- 提示、13种操作报价、严格选择规格、禁用原因和结构化预览；
- 聊天消息；
- 完整对局快照；
- 客户端对局命令及3种严格命令载荷；
- 命令接受与拒绝；
- 16种客户端表现事件及其严格载荷。

## 二、构建与校验

```powershell
node tools/build-client-protocol.mjs
node tools/validate-client-protocol.mjs
```

修改Schema后必须重新生成类型。校验器发现生成文件与Schema不一致时会重新生成并失败，要求开发者确认变更后再次运行。

## 三、当前边界

- 首批Schema聚焦已经进入对局后的服务器视图、操作报价和命令结果。
- `GameCommand`当前正式限定为`EXECUTE_OFFER`、`SET_PRESELECTION`和`SEND_CHAT`。
- 创建/加入房间、准备、座位调整和角色选择已在`room-protocol.schema.json`中单独定义，避免把大厅生命周期混入对局命令。
- `InteractionOffer.selectionSpecs`统一表达选牌、选目标、选项、数字、颜色、方式和确认；可选与超时行为由报价明确下发。
- `InteractionOffer.preview`只允许公开摘要、费用变化、伤害段预览和警告，不得夹带隐藏规则状态。
- `GameCommand.payload`只允许执行报价、设置武器预选和发送聊天三种载荷；`x-commandPayloadMap`用于运行时按命令名选择对应Schema。
- 16种表现事件均已进入`x-eventPayloadMap`；角色受伤、死亡、解除濒死和淘汰共用角色状态载荷。
- 标准Schema的联合类型负责限制允许的载荷形状；运行时验证器还必须按`x-commandPayloadMap`和`x-eventPayloadMap`执行名称—载荷关联校验。
- 当前类型生成器和无依赖验收器只实现本项目使用的JSON Schema子集；服务器和客户端入口仍需在实际工程中接入标准Draft 2020-12验证器，并保留本项目跨字段校验。

## 四、安全约束

- `PrivateView.hand`只允许出现在对应玩家的投影中；类型存在不代表可以广播。
- `concealedChoices`只能包含`concealed:`引用，运行时投影器需要额外验证引用作用域。
- TypeScript类型不能保证权限，权限必须在服务器投影前执行。
- Vue只消费生成类型，不导入权威规则执行对象。
