## 二、本轮修复（均为真实缺陷，非测试绕过）

### 2.1 地狱火即时伤害时序（`server/src/engine/combatScheduler.ts`）

- 现象：攻击者是恶魔术士（`character.demonmancer`，初始天赋 `talent.hellfire`）时，攻击造成实际伤害后触发地狱火判定；判定干预全部 pass 后 `finalizeJudgment` 把地狱火伤害排入 `immediate.damagePipeline`，而 combatScheduler 在攻击仍结算中（`combat.attack` 未清空）执行它，`executeNextImmediateDamageEffect` 抛 `DIRECT_DAMAGE_NOT_STABLE`。
- 修复：地狱火即时伤害等攻击结算完成后再执行（`isPendingHellfireDamage(current) && !current.combat.attack`）。

### 2.2 三处漏 push 领域事件（`druid.ts` / `trapMaster.ts` / `laserFishWeapon.ts`）

- 现象：`STATE_EVENT_SEQUENCE_GAP` 偶发断号（E2E 约 1/8 概率复现）。断点位于 `dying.enter`（rev N）与 `dying.rescue.window.opened`（rev N+2）之间，缺失一个事务的事件。
- 根因：三个事务 commit 后未把事件写入 `state.history.domainEvents`（`lastEventSeq` 已推进但历史缺失）：
  - `druid.ts` `processVineAfter`（藤蔓命中施加摸牌修正）；
  - `trapMaster.ts` `grantBombsAfterAttack`（陷阱炸弹累计发牌）；
  - `laserFishWeapon.ts` `clearInvalidLaserFishAim`（瞄准目标不可用时清除瞄准）。
- 修复：三处 commit 后补 `history.domainEvents.push(...events)` 与 `validateAuthoritativeState`。

## 三、E2E 测试修复（`server/src/app/e2e.test.ts`）

原 E2E 卡在第一次攻击响应 pass（124 文档记录的 `OFFER_HANDLER_NOT_REGISTERED`）。逐层修复：

1. **窗口排干**：攻击命中后会出现角色技能（`wizardSpellStrike` 等）、判定干预（`judgmentIntervention`）、濒死救援（`dyingRescue`）等中间窗口，新增 `drainWindows` 循环对每个可达窗口按其合法 offer（优先 pass）提交，直到回到 `playPhaseAction` 或对局结束。
2. **权威状态驱动**：出牌窗口按 `pendingWindows` 中 `playPhaseAction` 的当前 `promptId` 匹配客户端快照，修复旧快照误匹配（攻击结算后新窗口 promptId 带后缀）。
3. **先查已有消息再等待**：`waitFor`/`snapshotFor` 先搜索客户端已收到的消息，修复"消息在等待开始前已到达"导致的索引错过（观战 `winnerTeam` 快照、濒死快照均曾因此超时）。
4. **选角避开特殊生命层角色**：目标角色避免 `character.punching_bag`（额外 12 血）与 `character.interdimensional_traveler`（血量下限 3），保证"hp=1 一击必杀"场景成立（四候选不可能全为特殊角色，必可选到普通角色）。
