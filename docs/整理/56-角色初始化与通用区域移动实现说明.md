# 角色初始化与通用区域移动实现说明

## 一、角色初始化

`createInitialSetup`现在必须接收四座`characterIdsBySeat`，并从冻结`characters.json`读取角色数据。未知角色ID立即拒绝创建，不允许用默认角色静默替代。

每名玩家在发牌前已初始化：角色ID、当前/最大血量、当前/最大护盾、铁盾、初始天赋ID和技能ID。当前血盾均从对应上限开始；初始天赋是角色固有能力列表，不作为普通天赋卡放入装备槽。

权威状态不变量新增“角色必须完成初始化”，禁止空角色或空血盾数据进入开局投影和正式对局。

## 二、通用区域移动

新增`moveCard`原子操作，输入包含卡牌实例、目标区域、明确`moveKind`、插入位置和可选正反面状态。支持的移动语义与DSL规范一致，包括摸牌、打出、响应、弃置、失去、获得、给予、装备、替换、拆除、合成消耗、变形、展示、判定、返回、移除和系统移动。

执行会在同一事务中：验证实例和区域→从原区域有序列表移除→插入目标区域→更新卡牌`zoneRef/owner/controller/faceUp`→产生`card.moved`→提交修订及领域历史→验证全状态不变量。任一验证失败不修改原状态。

当前只实现最小单卡移动原语；装备容量、替换触发、牌堆耗尽重洗等上层规则由后续专门执行器组合，不能塞进通用移动函数暗中处理。
