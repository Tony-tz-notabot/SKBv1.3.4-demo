# v1.3.4 规则包冻结审计

本文记录规则包进入实现前的跨包一致性检查。它不新增玩法裁定；发现正文与结构化数据冲突时，仍按既定来源优先级处理。

## 一、本轮结论

- 事实层共 203 种卡牌；武器、非BOSS、BOSS三个执行规则包分别覆盖 66、128、9 种，合计203种。
- 三个分类规则包的卡牌ID互不重复，并与 `cards.json` 构成精确全集；缺失、重复或多余模板均会令校验失败。
- 非BOSS 128种模板引用的71个效果族全部存在；BOSS 9种模板引用的9个效果族全部存在。
- 事实层不再使用 `pending_dsl`。203种模板统一标记为 `encoded_in_category_rule_pack`，表示效果由分类执行规则包承载。
- 武器、非BOSS、BOSS的待编码数量均为0；G001-G043、R001-R050、W001-W053、P001-P052、B001-B050均已唯一映射。
- 按规定顺序连续重建后，全部JSON文件的SHA-256保持不变，当前生成过程可复现。
- 全量校验结果为 `ok`。缺少6项专属素材仍由既定占位图策略处理，不属于规则语义缺失。

## 二、已加入的强制约束

`tools/validate-ruleset.mjs` 当前会阻止以下状态进入规则包：

1. `cards.json` 仍含待编码或其他非最终效果状态；
2. 任一卡牌没有且仅有一个所属分类执行模板；
3. 分类执行模板引用不存在的卡牌事实；
4. 非BOSS或BOSS模板引用不存在的效果族；
5. 效果族ID、卡牌ID或测试映射重复；
6. 已知测试未映射、规则监听未知事件或效果使用未知操作；
7. 循环效果没有明确的最大迭代次数。

## 四、冻结前剩余工作

当前完成的是“结构、引用、覆盖与可复现性”审计。下一步单独进行事件可达性审计：检查每条监听事件是否存在合法生产者、关键事件链是否能从阶段入口到达，以及持续效果是否均有可达的清理节点。通过并修复后，才把v1.3.4机器规则包标记为冻结基线。

## 五、事件与持续期审计进度

第一阶段已完成静态事件引用和显式持续实例检查：

- 本体事件由215种补全为220种，补登记正文时间轴已经定义的`card.use.declare`、`card.use.committed`及三个`card.effect.*`事件；
- 修正6处不可解析引用：阶段名不再拼入事件名，统一改为`phase.start/body/after`加阶段过滤条件；`damage.modifier`统一为`damage.modified`；
- 校验器现在递归扫描所有规则包中的静态`listen`、`event`和`eventType`引用；动态`$event`引用在运行时按事件类型校验；
- `createDuration`必须使用统一`expiry.point + expiry.skipPolicy`结构；游侠翻滚、恶魔术士铁盾、狂战士暴击和羊叫兽禁闪持续期已完成规范化；
- 当前全量校验通过，静态未知事件引用为0，显式`createDuration`缺少到期边界为0。

剩余审计项是建立事件生产者集合和关键管线图，确认每个被监听事件不仅“名称合法”，而且能从核心阶段、动作或效果操作实际产生。

第二阶段已建立`event-production.json`：

- 当前规则包实际静态引用62种事件；
- 以10个生产者声明覆盖核心对局/阶段、动作、卡牌、攻击、响应、判定、伤害、濒死淘汰、效果结果及服务器边界；
- 每个静态事件只能归属一个生产者声明，避免同一事件由两个底层子系统争夺权威；
- 校验器同时禁止“引用事件无生产者”“生产者声明未知事件”“重复生产者ID”和“重复事件归属”；
- `event-production.json`已加入版本清单，服务器实现应以此确定事件所有权边界。

当前62种实际引用事件均已有生产路径。下一步检查关键管线之间的连接边：例如`createAttack`必须进入攻击管线、`createDamage`必须进入伤害管线、伤害后必须按条件进入濒死管线；完成后才能证明从阶段入口到监听器的端到端可达性。

第三阶段已建立`pipeline-graph.json`：

- 定义15条权威管线和27条有原因说明的连接边；根入口为`gameLoop`与`serverBoundary`；
- 对局循环可达回合、阶段和主动动作；动作可进入卡牌、攻击或能力流程；
- 效果执行可进入卡牌、攻击、响应、判定、伤害、濒死和持续期流程；
- 攻击命中进入伤害流程，每个目标伤害后进入濒死检查；伤害流程也可按血量条件进入濒死；未解除濒死进入淘汰，再回到胜负检查；
- 持续期在激活、到期或清理时重新进入效果执行流程，因此延时效果不是悬空数据；
- 14种管线入口操作已明确绑定，包括`createAttack`、`createDamage`、`checkDying`、`judgeColor`、响应操作、卡牌使用操作及持续期操作；
- 校验器禁止未知管线、悬空连接边、不可达管线、未知入口操作和未绑定的必需入口操作。

至此，当前规则包的静态事件引用已具备从入口、管线、生产者到监听器的完整可达路径。冻结前剩余工作转为最终发布检查：版本状态、生成物哈希、允许保留的素材占位项，以及构建命令的一键化。

## 六、冻结结果

最终发布检查已完成：

- `manifest.json`状态已设为`frozen_baseline`；
- `tools/build-ruleset.mjs`成为唯一完整构建入口，按正确依赖顺序生成四类数据并执行最终校验；
- `freeze.json`记录16个规则文件的SHA-256，校验器会拒绝文件集合或内容哈希变化；
- 6项允许缺少的专属素材已精确固定为：将军角色图、白金币、红金币、火盾、坐骑M08、特殊牌SP11；每项均必须保留类别回退键；
- 连续两次完整构建所得`freeze.json`哈希一致，冻结产物可复现；
- 最终全量校验结果为`ok`。

v1.3.4机器规则包现已冻结。后续任何玩法、数值、模板、事件或DSL变化都应创建新的版本或明确解除冻结并重新生成哈希，不得直接修改冻结JSON后绕过构建。
