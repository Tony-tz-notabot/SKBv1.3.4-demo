# v1.3.4 客户端功能与界面约束

状态：已由规则作者确认，作为Vue 3客户端设计与实现基线。本文只规定显示、交互和权限边界，不改变服务器权威规则。

## 一、聊天

- 房间准备阶段和对局内均提供“全部”与“队伍”两个聊天频道。
- 全部频道对房间内四名玩家可见；队伍频道只对固定队友可见：1/4号一组，2/3号一组。
- 频道权限和历史补发由服务器执行，客户端不得仅靠隐藏组件保护队伍消息。
- 聊天与规则结算日志分离，可以独立折叠、关闭提示或屏蔽玩家。
- 每条消息至少显示发送者、座位、频道和发送时间。

## 二、角色详情

- 角色选择和对局内均可查看角色详情。
- 统一支持长按；电脑端另可支持右键或详情按钮。
- 角色选择阶段只能查看自己有权限得知的候选，不能泄露他人的候选或预选。
- 详情包括立绘、名称、初始血盾、初始天赋、技能、当前实际状态、次数、CD、持续效果及当前修正。

## 三、卡面构成

卡面不采用把全部文字和动态状态预先烘焙进单张图片的方案，统一由以下部分组合：

1. HTML/CSS实现的统一卡框和布局；
2. `assets`中的原始卡牌或装备图片作为主图；
3. 冻结规则包提供名称、颜色、类别、基础数值和规则摘要；
4. 服务端玩家视图提供当前状态、次数、耐久、蓄力、CD、失效和其他动态角标。

图片通过`resourceKey`加载，禁止在业务组件中写死路径。缺图按专属图片→类别占位图→通用占位图降级，不显示浏览器破损图片。

## 四、无需进入详情即可看到的信息

场上和手牌中的卡牌在正常尺寸下至少显示：

- 名称；
- 印刷颜色；
- 卡牌类别；
- 当前操作所需的核心数值，如射程、伤害结构、耐久、蓄力或距离修正；
- 必要状态角标，如当前方式、失效、选中、CD和剩余次数；
- 能在当前尺寸可靠阅读的简化效果关键词。

完整规则正文、来源、动态修正明细、持续期解释和合成路线放入详情面板。小卡面不得因塞入完整长文本而失去可读性。

## 五、可操作高亮

- 当前可操作对象使用明亮描边或轻微发光；当前已选对象使用更强且稳定的选中描边。
- 合法目标显示目标环；必须完成的操作增加脉冲提示。
- 响应窗口只高亮当前合法的手牌、装备、武器和技能。
- 当前不可操作对象降低亮度；通常可用但当前不合法的对象可点击查看服务器给出的具体原因。
- 武器的“当前预选常亮”“当前可发动”“当前方式”和“失效”必须使用不同视觉语义。
- 高亮依据只能来自服务器下发的`legalActions`、`legalTargets`和`legalResponses`。客户端可做视觉预览，但不得自行裁定最终合法性。
- 高亮不得泄露隐藏信息，尤其不能暗示其他玩家某张手牌的真实身份或可响应能力。

## 六、实现边界

客户端负责状态展示、详情、动画、预选和提交意图；服务器负责合法性、费用、目标、随机、判定、响应、伤害、状态到期、濒死与胜负。任何客户端高亮和预览都不构成规则承诺，命令提交后仍以服务器结果为准。

## 七、座位视角旋转

- 房间、选角与对局场面按当前观看者座位旋转，本地玩家始终显示在下方；
- 按规则逆时针的下一座显示在右侧，对座显示在上方，上一座显示在左侧；
- 旋转只改变屏幕位置，不改变真实座位号、队伍、距离、回合顺序或结算顺序；
- 观战者没有座位时采用1号座位视角作为默认投影，后续可增加观战视角切换。
