# 131-中央战斗区大改原始需求记录（作者原话）

> 状态：**作者原始需求记录**（2026-08 第四轮）。本文件只记录原话与结构化梳理，**不含设计决策**；设计见 `docs/整理/132-中央战斗区与对局动画总设计.md`。
> 前置说明：作者确认"特殊状态图标（铁盾等）到时候使用图标，不过先这样吧"——即 130 §1.5-B 的"特殊状态图标行"先用文字芯片，图标化后置。

## 1. 原始需求（作者原话，未改动）

> 1. 移除原来的牌堆、展示区、弃牌堆，统一重做。
> 2. 先设计所有操作指示箭头，由操作方指向被操作方，且包含自己指向自己的。设计为类似于作战地图上那种整体较宽，尾巴宽且中间自然凹陷，主体左右均为弧线，箭头大的那种。指向自己的类似但整体绕成一个圈；若同时有多个目标的操作则显示多个箭头；还有可能来自或到中央区域的一端无源箭头。
> 3. 若操作选完目标待对方响应是只有白色系荧光轮廓；(以攻击操作为例）若对方成功使得你全部效果无效则淡出，若不需响应或命中等先轮廓实体化，然后根据具体效果如伤害、回复、获得牌、或其他效果，从箭头尾部向头部动画有不同但合适的颜色渲染且有冲击感，待到达目标后执行目标相应的动画效果(如扣血动画等等）。
> 4. 若前一个操作未结束已经出现了新的效果（如反击），那么原来操作的箭头透明度增高，先处理新的，待新的处理完再恢复透明度处理原来的。
> 5. 中央区域划分为主区、临时弃牌区、牌堆和弃牌堆。刚打出或响应的牌先进入主区展示且主区会有所有人可见的文字词（类似于操作提示词，但所有人可见，用于看当前在进行什么，如谁用什么东西对谁干了什么，参数、效果等；或谁的什么什么判定，若怎样什么效果之类的。类似于操作提示词的要求（见操作提示词的相关文档），但没有什么后果之类的（用于给所有角色体现对局而不是提示操作））。判定和展示牌也在主区显示。每当操作进行到下一步时候主区的牌按顺序整齐摊开排列在临时弃牌堆，待整个操作结束（如一整次攻击的攻击、响应、判定等等），所有临时弃牌的牌进入弃牌堆。主区和临时弃牌区较大。弃牌堆则较小，是一个条状结构，容放其长度的牌，它没有拖动条，超出了就不显示了，是队列结构有大小限制；牌堆则只显示叠放的卡牌的背面及数量。
> 6. 所有摸牌从中央牌堆（或他人区域）移动牌到相应的角色区，但不和摸牌效果的动画矛盾，只是所有人都可以看到，依据是否公开决定这些牌是否正面还是背面。
> 7. 判定、展示从牌堆翻需要数量的牌到主区。判定成功的响应词条高亮，相应牌也高亮且边缘发出相应颜色的光；判定失败的卡牌变暗。
> 先这样。这是一个大项目，要做好计划。所有改动要求用TDD方法，以测试为依据且要防止回归bug。具体你不确定的请务必复习相关规则和要求。

## 2. 结构化梳理（实施视角，不含设计决策）

| 编号 | 主题 | 要点 |
|---|---|---|
| R1 | 中央区整体重做 | 移除原牌堆/展示区/弃牌堆三块静态展示，重新划分为四个子区（见 R5） |
| R2 | 操作指示箭头 | 操作方→被操作方；含自指（绕成圈）；作战地图风格：整体较宽、尾巴宽且中间自然凹陷、主体两侧弧线、箭头大；多目标=多箭头；来自/到中央区的一端可为"无源"箭头 |
| R3 | 箭头状态机（以攻击为例） | ①选完目标待响应：仅白色系荧光轮廓；②对方使全部效果无效：淡出；③不需响应/命中：轮廓实体化 → 按效果类型（伤害/回复/获得牌/其他）从尾部向头部以不同且合适的颜色动画渲染、有冲击感 → 到达目标后执行目标对应动画（如扣血动画） |
| R4 | 嵌套操作 | 前一操作未结束又出现新效果（如反击）：原箭头透明度增高→先处理新的→新的处理完→恢复透明度处理原来的 |
| R5 | 中央区四子区 | ①主区：刚打出/响应的牌进入展示；全员可见文字词（谁用什么对谁干了什么、参数/效果；或谁判定、若怎样什么效果）——风格同操作提示词（见 128）但用于"体现对局"而非"提示操作"；判定和展示牌也在此显示；②临时弃牌区：操作每进行到下一步，主区的牌按顺序整齐摊开排入；整个操作结束（如一次完整攻击的攻击/响应/判定等）后全部进入弃牌堆；主区与临时弃牌区较大；③弃牌堆：较小、条状、按长度容纳、无滚动条、超出不显示、队列结构有大小限制；④牌堆：只显示叠放的卡背+数量 |
| R6 | 摸牌动画 | 从中央牌堆（或他人区域）移动到相应角色区；不与摸牌效果动画矛盾；所有人可见；按公开性决定正面/背面 |
| R7 | 判定/展示动画 | 从牌堆翻所需数量到主区；判定成功的响应词条高亮、对应牌高亮且边缘发出相应颜色光；判定失败的牌变暗 |
| R8 | 方法要求 | 大项目、做好计划；不确定处复习相关规则；**全部改动 TDD，以测试为依据，防止回归** |

## 3. 开放问题（设计时逐项回答，答案见 132）

1. "操作"的粒度与聚合键：一次攻击（声明→响应→判定→伤害→结束）如何从事件流识别为一个操作组？反击/连锁如何嵌套？
2. "全员可见文字词"的数据来源：服务端新增公开叙述字段 vs 客户端从演示事件/日志派生的取舍（见 132 数据管线）。
3. 摸牌"所有人可见但按公开性决定正/背面"：现有 CARD_DRAWN 对他人是否折叠？是否需服务端公开层补充？
4. 判定成功/失败结果与判定卡 ref 的公开可见性；"响应词条高亮"对应事件。
5. 主区/临时弃牌区/弃牌堆的尺寸与四角面板、血盾条改造后的可用空间。
6. 弃牌堆"条状队列有大小限制"：限制多少张、超出策略（只显示最新 N 张？）。
