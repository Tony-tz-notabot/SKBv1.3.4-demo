# SKB v1.3.4机器数据规范

状态：v1.3.4机器规则包冻结基线。本文定义事实层、执行规则包与冻结校验边界。

## 技术承载约束

- 客户端确定采用Vue 3，默认使用TypeScript及组合式API。
- Vue客户端消费服务端过滤后的公开/私有视图，负责展示、动画、预选和提交操作意图，不在本地裁定合法性、随机结果或伤害结算。
- JSON/DSL规则包与Vue解耦，保持语言无关；服务端权威规则引擎的实现语言另行确定。
- 后续可从JSON Schema生成TypeScript类型，但生成类型只约束数据形状，不替代服务端规则校验。

## 一、目录与职责

`rulesets/v1.3.4/`是服务器可直接加载的版本包：

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 规则包身份、状态、文件入口及正式正文来源 |
| `settings.json` | 全局人数、座位、默认数值、规则开关与超时策略 |
| `characters.json` | 25名角色稳定ID、基础血盾和初始天赋显示名 |
| `cards.json` | 全部卡牌模板的稳定ID、类别、颜色、初始数量和资源键 |
| `deck.json` | 初始牌库中实际加入的模板及数量 |
| `resources.json` | 角色/卡牌资源键、实际素材路径、回退键及素材库存 |
| `resource-mapping.json` | 中文同名素材解析、类别目录、扩展名、别名、回退策略和允许缺图白名单 |
| `ontology.json` | 时间、事件、效果操作及枚举本体 |
| `dsl.schema.json` | 效果DSL的JSON Schema |
| `core-rules.json` | 阶段、动作、攻击、伤害、濒死管线及基础状态 |
| `dsl-examples.json` | 通过结构校验的最小DSL示例 |
| `general-rules.json` | G001-G045映射的通用管线、触发器、不变量和安全策略 |
| `character-rules.json` | 57个角色能力模板及R001-R050规则映射 |
| `weapon-rules.json` | 66种武器模板、攻击模式及W001-W053追踪 |
| `nonboss-rules.json` | 128种非BOSS模板、71个效果族及P001-P052追踪 |
| `boss-rules.json` | 9种BOSS模板、公共策略、9个效果族及B001-B050追踪 |
| `event-production.json` | 实际引用事件的唯一生产者与系统所有权 |
| `pipeline-graph.json` | 核心管线、连接边及效果操作入口映射 |
| `freeze.json` | 冻结文件SHA-256与允许缺失的专属素材白名单 |

`tools/build-ruleset-data.mjs`只在构建时读取v1.3.4单一正文并生成上述JSON。服务器运行时不得读取Markdown，也不得根据中文显示名推断规则。

## 二、稳定性要求

- `characterId`、`cardId`、`resourceKey`是稳定业务标识；显示名和素材文件名可变。
- 初始牌数量只存于`cards.json`并投影到`deck.json`；校验必须保证两者一致。
- `count=0`模板保留在`cards.json`，但不进入`deck.json`。
- 雕像五色展开为50个独立模板；基础牌按印刷颜色展开为22个模板。
- 所有数值、颜色、规则开关和超时策略均由规则包读取，业务代码不得散落硬编码。

## 三、当前边界

`cards.json`只保存可无歧义提取的卡牌事实；效果由武器、非BOSS和BOSS分类规则包承载。全部分类效果完成后，事实模板统一使用`effectEncodingStatus: "encoded_in_category_rule_pack"`，服务器必须通过分类规则包的稳定`cardId`绑定效果，不能把`ruleSource`当作运行时效果。

通用、角色、武器、非BOSS和BOSS效果均已完成结构化，并全部映射G/R/W/P/B验收编号。服务器加载时必须先验证`freeze.json`，不得加载哈希不一致或状态不是`frozen_baseline`的版本包。

## 四、构建与最低校验

在仓库根目录执行：

```powershell
node tools/build-ruleset.mjs
```

必须满足：

- 角色25名；
- 武器模板66种，初始61张；
- 非BOSS非武器牌267张；
- BOSS 9张；
- 初始牌库合计337张；
- 所有角色ID、卡牌ID、资源键唯一；
- 所有`deck.json`条目能在`cards.json`找到且数量大于0。
- 16个冻结文件的SHA-256与`freeze.json`一致；
- 缺少专属素材的资源键必须与冻结白名单精确一致，并具有类别回退键。
