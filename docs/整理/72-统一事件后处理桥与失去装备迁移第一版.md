# 统一事件后处理桥与失去装备迁移第一版

状态：统一提交后事件泵及首个真实事件生产点已接入。

## 提交后事件泵

- `processCommittedEventTriggers` 接收一次已经原子提交的领域事务，按原事件顺序派发触发，并递归处理触发产生的新事件。
- 返回值保留原事务修订号，并统一报告触发步数、停止原因及待处理触发ID。
- 重复处理同一事件时，以“事件键＋触发ID＋来源实例”去重；最大递归步数继续读取版本设置 `settings.engine.autoAdvanceMaxSteps`。
- 遇到可选窗口、同角色排序、费用/选择窗口或安全上限时显式停止，不越过玩家决策。

## `card.lost` 生产点

- 通用区域移动离开武器、第三武器、防具、坐骑、天赋或BOSS生效区时，同时产生 `card.moved` 与 `card.lost`。
- `card.lost` 保存离场前的模板ID、控制座位、区域引用和区域类型，以及目标区域和移动语义；牌已经移走后仍可据此匹配自身离场效果。
- `moveCardAndProcessTriggers` 已使用统一事件泵。血箱因控制者失去防具而回复2点血量已通过真实冻结规则执行，不再依赖牌名硬编码。
- 战斗内防具耐久耗尽的两处生产点也已统一写入相同离场快照，为后续战斗调度器桥接做准备。

## 当前边界

- 普通 `moveCard` 仍保留为纯原子移动原语；规则动作入口必须使用带触发后处理的组合接口。
- 状态与战斗生产点尚未全部接入事件泵。冰盾当前仍有既有专用执行路径，在迁移前必须先消除重复执行风险。
- 同一控制者的多个同级触发、带费用触发和带目标/选牌触发仍会明确停止，由下一阶段专门窗口接管。
