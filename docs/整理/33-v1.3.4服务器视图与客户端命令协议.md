# v1.3.4 服务器视图与客户端命令协议

状态：实现规范第一稿。本文承接冻结规则包与已确认客户端约束，规定服务器权威状态如何投影给Vue 3客户端，以及客户端可以提交什么意图。本文不新增玩法规则。

## 一、核心原则

1. 服务器保存完整对局状态，客户端只保存服务器视图、未提交的界面选择和动画队列。
2. 客户端不得读取规则DSL后自行计算合法操作；服务器下发当前玩家可用的`actionOffers`、`targetOffers`和`responseOffers`。
3. 客户端提交`offerId + 玩家选择`，服务器重新检查身份、版本、状态修订号、提示窗口和全部合法性。
4. 公开、队伍、个人和服务器私有信息在服务端投影阶段分离，不能先发送完整状态再由Vue隐藏。
5. 规则事件和客户端动画事件分层。客户端接收已过滤的表现事件，不依赖DSL内部对象形状。

## 二、标识与顺序

服务端至少使用以下稳定或局内标识：

| 字段 | 含义 |
| --- | --- |
| `gameId` | 对局ID |
| `rulesetVersion` | 固定为本局加载的规则版本 |
| `stateRevision` | 每次权威状态提交后递增，用于拒绝过期命令 |
| `eventSeq` | 每个已公开表现事件递增，用于补发和动画排序 |
| `commandId` | 客户端生成的幂等ID；重复提交只返回原结果 |
| `promptId` | 当前选择/响应窗口ID；窗口关闭后旧ID立即失效 |
| `offerId` | 某次视图修订下的合法操作报价ID |
| `instanceId` | 服务器内部真实卡牌实例ID；仅按权限公开 |
| `publicRef` | 对所有玩家稳定公开的对象引用 |
| `privateRef` | 只对当前玩家有效的对象引用 |
| `concealedRef` | 仅在某次隐藏选择中有效的牌背引用，结束后失效 |

`stateRevision`负责并发一致性，`eventSeq`负责表现补发，两者不能混用。

## 三、服务器完整状态边界

服务器权威状态至少分为：

```text
GameState
├─ identity：gameId、ruleset、房间设置、随机源状态
├─ lifecycle：轮、回合、阶段、当前优先权、计时
├─ seats[1..4]：用户、队伍、连接、角色、在场/死亡/淘汰状态
├─ zones：牌堆、弃牌堆、手牌、结算区、判定区和全部装备槽
├─ cardInstances：模板、印刷颜色、当前模板、来源、区域和公开状态
├─ combat：攻击、目标队列、响应栈、伤害段和濒死栈
├─ effects：状态、限制、标记、次数、CD、蓄力、持续期和延时效果
├─ prompts：当前必须处理的选择与响应窗口
├─ preselection：每名玩家的武器槽和主动方式预选
├─ history：规则事件、公开表现事件、私密事件和命令结果
└─ chat：全部频道与两个队伍频道
```

牌堆完整顺序、他人手牌、未公开候选、随机源、规则执行栈和服务器私密事件不得进入普通客户端视图。

## 四、客户端快照

完整快照使用统一外壳：

```json
{
  "type": "GAME_SNAPSHOT",
  "gameId": "game_01",
  "rulesetVersion": "1.3.4",
  "stateRevision": 482,
  "lastEventSeq": 913,
  "serverTime": 1785480000000,
  "viewer": { "userId": "u1", "seat": 1, "team": "A" },
  "publicView": {},
  "privateView": {},
  "interaction": {},
  "chat": {}
}
```

### 4.1 `publicView`

所有在房间内且有观看权限的人可见：

- 固定座位、队伍、昵称、连接和准备状态；
- 当前轮、回合玩家、阶段、阶段是否被跳过/替换；
- 各角色公开身份、血量、护盾、铁盾和特殊生命层；
- 在场、离场、死亡未淘汰、死亡和淘汰状态；
- 手牌数量，不含他人手牌身份；
- 公开装备、天赋、BOSS、判定区、状态、标记、CD、蓄力和次数；
- 牌堆数量；弃牌堆最后允许展示的几张公开牌；
- 中央正在结算的牌、攻击、目标顺序、响应者、判定和伤害段；
- 已公开的倒计时和胜负状态。

### 4.2 `privateView`

只发送给当前玩家：

- 自己的完整手牌实例及可见基础信息；
- 自己的私密角色候选和选择状态；
- 仅自己可见的选择结果、来源信息和私密日志；
- 自己当前武器槽/方式预选；
- 当前提示所需的隐藏候选牌背，不含其真实模板或正面资源。

队伍信息不能放在通用`privateView`后广播，而应由服务器分别为A、B队生成投影。

## 五、用于卡面和角色面板的视图模型

客户端不直接组合多份规则JSON。服务器为可见对象输出统一展示模型：

```json
{
  "ref": "public:card_187",
  "templateId": "weapon.w01",
  "displayName": "火焰之鹰",
  "category": "weapon",
  "printedColor": "green",
  "resourceKey": "card.weapon.w01",
  "summary": "射程2｜普通2｜判橙追加火1×2",
  "coreStats": [
    { "key": "range", "label": "射程", "value": 2 },
    { "key": "damage", "label": "伤害", "value": "2" }
  ],
  "badges": [],
  "state": {
    "effective": true,
    "selected": false,
    "modeId": "default",
    "charge": 0,
    "durability": null,
    "cooldown": null
  },
  "detailAvailable": true
}
```

`summary`和`coreStats`由规则包展示适配层生成，不由Vue解析中文正文。详情请求可返回更完整的当前效果、来源、持续期与修正明细。

## 六、交互报价

服务器在`interaction`中下发当前玩家能做什么：

```json
{
  "prompt": {
    "promptId": "prompt_71",
    "kind": "playPhase",
    "mandatory": false,
    "deadlineAt": 1785480016000
  },
  "offers": [
    {
      "offerId": "offer_attack_1",
      "kind": "declareAttack",
      "sourceRefs": ["private:hand_kill_3"],
      "targetRule": { "min": 1, "max": 1, "distinct": true },
      "legalTargetRefs": ["public:seat_2", "public:seat_3"],
      "requiredSelections": ["killCard", "targets"],
      "preview": {
        "weaponRef": "public:weapon_12",
        "modeId": "default",
        "range": 2,
        "damageStructure": "2"
      }
    }
  ],
  "disabledHints": [
    {
      "subjectRef": "private:hand_card_8",
      "reasonCode": "WRONG_PHASE",
      "messageKey": "action.wrongPhase"
    }
  ]
}
```

客户端高亮只消费`offers`：

- `sourceRefs`决定可操作对象；
- `legalTargetRefs`决定合法目标；
- `mandatory`决定是否使用必须操作脉冲；
- `disabledHints`只用于玩家有权知道的失败原因；
- 不得为他人隐藏手牌生成可关联的高亮数据。

报价是当前修订的快照，不是永久许可。命令提交时服务器必须重新校验。

## 七、客户端命令外壳

所有会影响服务器状态的请求使用：

```json
{
  "type": "GAME_COMMAND",
  "commandId": "cmd_client_uuid",
  "gameId": "game_01",
  "expectedStateRevision": 482,
  "promptId": "prompt_71",
  "offerId": "offer_attack_1",
  "command": "EXECUTE_OFFER",
  "payload": {
    "selections": {
      "killCard": ["private:hand_kill_3"],
      "targets": ["public:seat_2"]
    }
  }
}
```

服务器返回：

- `COMMAND_ACCEPTED`：包含`commandId`、新修订号和首次事件序号；
- `COMMAND_REJECTED`：包含稳定`reasonCode`、本地化键、当前修订号，以及是否需要刷新快照；
- 对重复`commandId`返回首次处理结果，不重复执行。

常见拒绝码：`STALE_REVISION`、`PROMPT_CLOSED`、`OFFER_EXPIRED`、`NOT_YOUR_PRIORITY`、`SELECTION_COUNT_INVALID`、`TARGET_NO_LONGER_LEGAL`、`COST_UNPAYABLE`、`OBJECT_NOT_VISIBLE`。

## 八、命令类型

### 8.1 房间与角色选择

- `CREATE_ROOM`
- `JOIN_ROOM`
- `LEAVE_ROOM`
- `SET_READY`
- `CHANGE_SEAT`
- `UPDATE_ROOM_SETTINGS`
- `KICK_PLAYER`
- `TRANSFER_HOST`
- `START_GAME`
- `PRESELECT_CHARACTER`
- `LOCK_CHARACTER`

### 8.2 对局操作

对局规则操作优先统一为`EXECUTE_OFFER`，由`offer.kind`区分：

- 使用/打出/响应卡牌；
- 发动技能；
- 攻击；
- 选择目标、牌、颜色、数字或方式；
- 装备、替换、主动弃装备、拆除；
- 合成；
- 判定干预；
- 濒死救援；
- 放弃可选发动；
- 结束阶段。

### 8.3 私人预选

武器预选不是规则动作，使用独立命令：

```json
{
  "command": "SET_PRESELECTION",
  "payload": {
    "weaponSlot": "weaponSlot:1",
    "modeId": "default"
  }
}
```

服务器保存为该玩家私有状态，不消耗资源、不进入公开规则日志。攻击报价读取已保存预选；没有有效预选时不生成合法攻击报价，并返回选择武器提示。空槽只有在所有武器槽均为空时才能产生手刀报价。

### 8.4 聊天

```json
{
  "command": "SEND_CHAT",
  "payload": { "channel": "team", "clientMessageId": "m1", "text": "……" }
}
```

频道为`all | team`。服务器按座位队伍投递、限长、限频、过滤权限并实现幂等；客户端不能自行决定队伍收件人列表。

## 九、表现事件

规则引擎完成状态提交后，由表现投影器生成客户端事件，例如：

- `PHASE_CHANGED`
- `CARD_MOVED`
- `CARD_REVEALED`
- `ACTION_COMMITTED`
- `ATTACK_TARGETED`
- `RESPONSE_WINDOW_OPENED`
- `RESPONSE_RESOLVED`
- `JUDGMENT_REVEALED`
- `JUDGMENT_RESULT_CHANGED`
- `DAMAGE_SEGMENT_APPLIED`
- `STATUS_CHANGED`
- `DYING_STARTED`
- `CHARACTER_RESCUED`
- `CHARACTER_DIED`
- `CHARACTER_ELIMINATED`
- `GAME_ENDED`

每项带`eventSeq`、`stateRevision`、可见对象引用和动画建议。动画可以跳过或加速，权威状态不能依赖动画是否播放完成。

## 十、增量、快照与重连

正常更新：

```text
命令接受
→ 服务器完成一次或多次规则提交
→ 按玩家权限生成表现事件
→ 发送最新视图补丁
→ 客户端按eventSeq播放
```

重连请求携带客户端最后确认的`eventSeq`与`stateRevision`：

- 事件仍在补发窗口内且基础修订兼容：补发缺失事件和最终补丁；
- 事件缺失、权限变化或修订不兼容：发送完整快照；
- 完整快照到达后，客户端丢弃旧报价、旧提示和未提交选择；
- 已发送但未确认的命令按`commandId`查询结果，不能盲目重发为新命令。

## 十一、Vue客户端边界

建议客户端状态分层：

```text
serverSnapshot：最后确认的服务器视图
interactionOffers：当前合法报价
uiSelection：本地尚未提交的选牌/选目标
animationQueue：按eventSeq排序的表现事件
connectionState：连接、延迟、重连和时钟偏移
uiPreferences：音量、详情、日志筛选、聊天折叠等
```

Vue组件不得直接修改`serverSnapshot`。命令接受前可以显示“等待服务器确认”，拒绝后清理或恢复`uiSelection`。Pinia等客户端状态库只管理投影和界面，不成为第二套规则引擎。

## 十二、首批实现验收

1. 他人手牌视图只有数量，网络响应中不存在其模板ID或资源键。
2. 隐藏手牌选择只含随机排列的`concealedRef`和统一牌背。
3. 所有可操作高亮均能追溯到当前`offerId`。
4. 过期修订、过期提示和重复命令均有确定结果。
5. 武器预选私密、无费用、不写公开日志；攻击直接读取预选。
6. 同一队伍收到队伍聊天，另一队和观战者收不到消息内容。
7. 重连后不会重复执行命令，也不会播放与快照冲突的旧动画。
8. 客户端断开或关闭动画不会影响服务器继续结算和超时处理。
