# 额外宝石濒死生命周期与死亡交牌窗口

## 一、首次濒死锁定

`talent.extra_gem`在控制者进入濒死、救援窗口打开前通过冻结`dying.enter`触发：立即摸3张，消费当前装备实例的一次额度，并创建绑定本次濒死流程的待结算效果。装备区失效时没有有效触发来源，因此既不摸牌也不消费额度。

实例额度记录在牌实例`runtime`，不是玩家的跨实例次数；待结算效果记录在权威`scheduledEffects`，以濒死角色引用区分嵌套流程。后续救援再次开窗不会重复摸牌。

## 二、救回结果

角色恢复到至少1点血量后，先产生`dying.rescued`，随后立即把额外宝石移到牌库外并清除待结算效果，再恢复外围攻击。移除使用统一事务内区域移动，因此保留`card.moved/card.lost`事实。

## 三、死亡结果

所有救援角色放弃后先确认死亡，但在淘汰及死亡替代前打开`extraGemDeathTransfer`强制窗口：

- 操作者为死亡角色控制者；
- 目标为当时所有在场且未淘汰角色；
- 必须选择一个目标，超时按权威随机源选择合法目标；
- 将死亡角色当时的全部手牌按原顺序交给目标；
- 交牌完成后把额外宝石移到牌库外，再继续普通淘汰、钢铁破浪者号或暗黑大骑士死亡替代流程。

命令校验游戏、修订、优先权、提示、报价及目标重验；相同命令ID幂等返回。

## 四、验证

已覆盖首次摸3、救回移除、死亡暂停淘汰、整手交付、强制随机超时及装备失效不消费。服务端37个测试文件、168项测试与TypeScript生产构建全部通过。
