# 创建房间设置与拒绝提示说明

## 一、创建房间表单

大厅创建入口现已直接生成协议 `RoomSettings`，覆盖全部八项设置：

- 房间名称；
- 是否允许游客；
- 是否允许观战；
- 回合时限；
- 响应时限；
- 预留时间；
- 规则版本；
- 泛称拆除是否可以拆除 BOSS。

规则版本只允许选择大厅服务器快照提供且客户端协议支持的版本。泛称拆除默认启用，符合当前正式设置。计时值只做协议结构要求的整数及最小值校验，客户端不另造玩法上限；服务器仍须权威校验全部设置。

加入表单会标准化六位房间号，明确提示排除 `0/1/I/L/O` 等易混淆字符，并支持以普通玩家或观战者身份加入。密码只进入创建或加入命令，不写入任何快照。

## 二、拒绝提示本地化

`client/src/localization/commandRejections.ts`集中把 `messageKey/reasonCode` 转成玩家可理解的中文提示：

- 优先使用已登记的 `messageKey`；
- 其次使用稳定 `reasonCode`；
- 未知代码使用不泄露内部细节的通用提示；
- `refreshRequired=true`时追加正在同步最新状态的说明；
- 原始代码折叠在“技术信息”中，便于排障但不作为主要文案。

当前覆盖通用过期、窗口、优先权、选择、目标、费用、可见性，以及房间不存在、已满、关闭、密码错误、观战/游客限制、版本不符、权限不足和限流等常见情况。

## 三、验收

- 生产构建通过：45 个模块。
- 自动测试通过：2 个测试文件、7 项测试；其中新增3项拒绝提示优先级、未知值降级和刷新提示测试。
