# 129-对局日志系统设计（match-log）

状态：已实施。对局详细日志记录在 log 区（`game-activity` 上半部），彩色渲染，不用"你"，每个玩家看到不同（隐藏他人手牌/隐藏选择）；每局结束在服务器端写 JSON 文件；赛后可在客户端界面查看该局完整日志（含彩色渲染+两模式切换）。
关联：`docs/整理/128-操作提示词系统设计.md`（配色与 token 体系同源）、`docs/整理/121-真实应用层与联机链路实现说明.md`。

## 1. 目标与原则

**目标**：log 区记录**实际发生的事件**——摸牌/出牌/装备/攻击声明/伤害段/护盾血量扣减/回复/状态/濒死/救援/死亡/淘汰/判定/回合阶段/胜负。两种粒度可切换：**摘要**（每动作一行）与**原子**（每个事件一行）。彩色渲染（复用 128 §4.0.1 三套 token 色系）。**不用"你"**——主语/宾语一律角色名（骑士/法师…），但关系色仍按查看者视角（自己绿/队友蓝/敌红）。**每个玩家看到不同**：摸牌只有本人见牌名，他人只见"N张牌"；隐藏选择（面朝下非手牌）无人见牌名；判定结果/装备/弃牌等公开信息全桌可见；观战同公开视角。

**原则**（与提示词系统一致）：
- 日志数据一律来自**服务端权威**：服务端在事件发生时刻用当时的提交后状态构建规范条目（含隐私作用域），按观众过滤后随 `GAME_SNAPSHOT.log` 下发。
- 服务端负责句子骨架组合+语义分类+卡牌印刷色；客户端只负责 char→角色名+关系色、card→牌名+卡牌色、ability→技能名、sem→语义色（复用 `promptRenderers` 现有函数）。
- 每局结束写 `server/data/logs/<gameId>.json`（含权威原始领域事件，可重放）；赛后 API 按用户座位脱敏返回。

## 2. 数据流

```
引擎事务 → state.history.domainEvents 追加（引擎内部 30+ 处，无需逐一挂钩）
  → server.ts 4 个 sync 调用点：MatchLogBuilder.sync(room) 差分构建（当时状态判定作用域）
  → AppRoom.gameLog.entries（内存+随房间持久化；建局时 initGameLog 固化 meta：displayName/角色/队伍）
  → sync() 内 lifecycle==="ended" → MatchLogStore.save() 写 server/data/logs/<gameId>.json
  → projection game()/spectator()：projectLogView 按 viewer 过滤 → snapshot.log（重连/刷新天然保留）
  → 客户端 MatchLogPanel（实时）/ MatchLogEntries（共享渲染核心，摘要/详细切换 + token 着色）
  → 赛后 GET /api/match-logs + /api/match-log/<gameId> → MatchLogListView / MatchLogView
```

**单一水印同步点**：`MatchLogBuilder.sync(room)` 按 `eventSeq > lastLogEventSeq` 差分构建新事件。在 server.ts 每次 `room.game` 被命令/超时改动后调用（此时 `room.game` 即"当时的提交后状态"，与按事件时刻判定隐私等价）：
1. `receive()` game 通道 `this.games.handle(...)` 后；
2. `receive()` room 通道 `this.rooms.handle(...)` 后（覆盖 DISBAND_ROOM 直接 push 的 `game.aborted`）；
3. `tick()` 超时循环后；
4. `testApi` 命中后。
另在构造器末尾 catch-up（覆盖重启恢复残留）。

**隐私作用域**（`scopeOf`）：`zoneRef` 以 `hand:` 开头→`hand:<ownerSeat>`（仅本人）；faceUp 非手牌→`public`；面朝下非手牌→`hidden`（无人见牌名）。在事件发生时固化进条目，局末终态重算会泄露（如"摸牌"的卡后来被弃置变为 faceUp，若局末重算会误公开）。

## 3. 协议扩展

`client-protocol.schema.json`：
- `LogToken`（oneOf 按 `t` 分派，`additionalProperties:false`）：`text{s}` / `char{seat}` / `card{templateId,color,scope}` / `ability{id}` / `sem{s,cls}`。`scope` pattern `^(public|hidden|hand:[1-4])$`。
- `LogEntryView`：`{seq,mode:summary|atomic,type,tokens}`。
- `GameSnapshot` 加可选 `log: LogEntryView[]`（不进 required；快照携带全量日志，重连天然保留）。

`shared/src/generated/client-protocol.ts` 由 `node tools/build-client-protocol.mjs` 重生成。

## 4. 服务端实现

### `server/src/app/matchLog.ts`
- 类型：`LogToken`（含 scope 的 card）、`LogEntry`、`GameLogMeta`（players 含 seat/userId/displayName/characterId/team）、`GameLog{meta,entries,lastLogEventSeq,seqCounter,finalized,endedAt?}`、`MatchLogFile`（文件记录）、`MatchLogSink`。
- `initGameLog(room)`：建局时用完整 `room.players` 固化 meta（displayName）；`lastLogEventSeq=0`（首批事件入日志）。
- `MatchLogBuilder.sync(room)`：差分构建；原子与摘要条目可并存（同事件各产一行）；`lifecycle==="ended" && !finalized` → 同步置位 `finalized` 并 `store.save()`（防重复写）。攻击帧 `Map<attackId,{attackerSeat,weaponTemplateId,weaponColor}>` 由 `attack.declare`/`attack.weapon.resolve` 维护，支持嵌套攻击。
- `projectLogView(entries,viewerSeat,cap)`：按观众过滤——card scope public 保留、`hand:<viewerSeat>` 保留、其余替换为 text"一张牌"；**type 感知折叠**：card.drawn 且全部 card token 不可见→折叠为单个"N张牌"。观战（null）同公开视角。

### 原子模式映射（type=事件名，每事件一行）
- game.start→"对局开始，char 先行"；turn.start→"第N回合 char 回合开始"；phase.before/start→"char 进入 X 阶段"；phase.end→"char 结束 X 阶段"；phase.skip→"char 跳过 X 阶段"。
- card.drawn→"char 摸到 card×n"；played→"打出 card"；equipped→"装备 card"；synthesized→"合成 card"；discarded→"弃置 card"；dismantled→"拆除 card"；lost→"失去 card"；gained→"获得 card"；transformed→"的 card 变为 card"；responded→"打出 card 响应"；revealed/displayed→"公开：card"；effect.resolved(statue)→"char 雕像 card 结算"。
- attack.declare→"char 发动攻击"；weapon.resolve→"char 用 card"；targeted→"攻击目标：char×n"。
- damage.applied→"对 char 造成 N 伤害"（+元素字）；damage.prevented→"char 的伤害被抵消"（payload 无 amount）；health.hpLost→"char 失去 N 生命"（sem-hp）；shield.shieldLost→"char 失去 N 护盾"（sem-shield）；shield.broken→"char 的护盾被击破"。
- hp/health.recovered→"char 恢复 N 生命"（sem-heal）；shield.recovered→"恢复 N 护盾"。
- status.applied/refreshed/stacked→"char 获得状态【id】"；removed/expired→"失去状态"；prevented→"免疫状态"。
- dying.enter→"char 濒死"；rescued→"char 救援 char（回到N血）"；death.occurred→"char 死亡"；elimination.occurred→"char 被淘汰"；game.victory→"X队 胜利"；game.aborted→"对局中止"。
- judgment.card.revealed→"判定翻开 card（颜色）"；finalized→"判定结果 A→B"。
- response.resolved/committed→"char 响应"；passed→"char 放弃"。
- deck.reshuffled→"牌库洗牌（N张）"；exhausted→"牌库耗尽"。
- ability.resolved/trigger.resolved→"char 发动 ability"；ability.passed/trigger.passed→"char 放弃发动 ability"。
- 其余（card.moved、damage.after/received/proposed/finalized/modified、response.window.*、choice.*、marker/counter/limit/cooldown/duration.*、attack 内部 legality/queued*/commit/after、value.changed、weapon.* 耐久等）→ 跳过（避免刷屏）。

### 摘要模式映射（type=结果事件，每动作一行）
- attack.target.after→"char 用 card 攻击 char：命中/未命中，护盾-N 血-N"（只用此事件聚合，**绝不累加 damage.applied** 防重复计数；攻击消耗牌 purpose 以 `attack.` 开头不产生摘要行）。
- card.played(非攻击消耗)/equipped/synthesized/discarded(非initialRedraw)/dismantled/lost→对应动词。
- ability.resolved/trigger.resolved→"char 发动 ability"；hp.recovered→"char 恢复 N 生命"；card.effect.resolved(statue)→"char 雕像 card 结算"；dying.rescued→"char 救援 char"；death/elimination/victory/aborted→同原子；judgment.finalized→"判定：A→B"；turn.start→"— 第N回合 char —"（分隔行）。

### `server/src/app/matchLogStore.ts`
- 仿 JsonPersistence 原子写（mkdir+.tmp+rename+队列串行化）。`save(gameId,payload)` 写 `<gameId>.json`；`list(userId)` 返回该用户参与过的对局 meta（读目录+过滤）；`read(gameId,userId)` 读文件并用 `projectLogView` 按该用户座位脱敏（非参与者→公开视角）。
- `MatchLogFile = {version, gameId, roomId, roomCode, rulesetVersion, startedAt, endedAt, winnerTeam, forfeited, forfeitedBySeat, firstSeat, players, summary[], atomic[], events[]（权威原始领域事件）}`。

### 挂载
- `types.ts`：`AppRoom` 加可选 `gameLog?: GameLog`（真实房随 skb-state.json 序列化；测试房不落库但写日志文件）。
- `roomService.ts`：三处建局后 `room.gameLog=initGameLog(room)`（LOCK_CHARACTER / resolveCharacterTimeouts / createTestRoom）。
- `main.ts`：`new MatchLogStore(SKB_LOG_DIR ?? resolve(root,"server/data/logs"))` 传入 `SkbApplicationServer`。
- `server.ts`：构造器建 `MatchLogBuilder`；4 个 sync 调用点；HTTP 加 `GET /api/match-logs?token=` 与 `GET /api/match-log/:gameId?token=`（token 经 `resolveSession` 解析 userId）。
- `projection.ts`：`game()`/`spectator()` 返回对象加 `log:this.logView(room,userId)`（`projectLogView` 按 viewer 座位过滤）。

## 5. 客户端实现

- `localization/logRenderers.ts`：`LogEntryLike`（宽容结构，兼容快照 readonly 与 API 可变数组）、`renderLogEntry(entry,ctx)`（char→`characterName`+`relationshipCls`、card→`【cardNameById】`+`cardCls`、ability→`abilityDisplayName`+sem-extra、sem→原样、text→无 cls）、`logContextFromSnapshot`。
- `components/MatchLogEntries.vue`（共享渲染核心）：摘要/详细切换按钮 + `<ol>` 顺叙可滚动 + token→着色 `<span>`。
- `components/MatchLogPanel.vue`（实时）：props `{snapshot}`，ctx 来自快照，渲染 `MatchLogEntries`。
- `views/GameView.vue`：`:156` 用 `<MatchLogPanel :snapshot="snapshot"/>` 替换原 `GameEventFeed`（已删除 GameEventFeed.vue）。
- `styles/base.css`：token 色作用域用 `:is(.prompt-hint,.offer-preview,.game-log)` 共享（关系色/卡牌5色/sem 全部语义色）；加 `.game-log` 面板与 `.game-log__list` 排版。
- 赛后查看：`LobbyView`"对局记录"入口 → `MatchLogListView.vue`（列表 meta）→ `MatchLogView.vue`（fetch 详情，ctx 来自 meta.players+userId，渲染 MatchLogEntries）；`network/matchLogs.ts` 封装 `fetchMatchLogs/fetchMatchLog`；`App.vue` 视图切换加 matchlog 态。

## 6. 验收口径

- log 区默认摘要一动作一行、可切详细逐事件；彩色渲染（rel-*/card-*/sem-*）；全文无"你"，一律角色名。
- 摸牌只有本人见牌名，他人见"N张牌"；公开信息（判定/装备/伤害）全桌可见；观战同公开视角。
- 每局结束 `server/data/logs/<gameId>.json` 已写（含 summary/atomic/events 与 winnerTeam/players）；重复 sync 不重复写。
- 赛后 API 列表/详情按用户座位脱敏；客户端列表+查看页可打开该局完整日志（两模式切换）。
- 协议校验（validateProtocol）、两端构建与全量测试通过。
- 浏览器实机验证：SKB_TEST_MODE + `?test=1`，`__skbHarness` 打一局——攻击摘要"骑士用【weapon.w01】攻击圣骑士：命中，护盾-2"、摸牌隐私（座位1见牌名/座位2见2张牌）、详细模式逐事件、认输后文件落盘、赛后 API 返回该局。
