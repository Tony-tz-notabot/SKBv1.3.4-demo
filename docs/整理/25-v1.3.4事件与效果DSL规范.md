# SKB v1.3.4事件与效果DSL规范

状态：规则引擎底层语义正式设计稿。本文先穷举引擎必须表达的通用语义；尚未编码的具体牌不得绕过本规范另造私有流程。

## 一、三层模型

规则引擎严格区分：

1. **时间点（timing point）**：流程边界，可开放触发、响应、替代或检查；
2. **事件（event）**：已经发生或正请求发生的事实，具有唯一`eventId`及因果链；
3. **效果（effect/op）**：读取上下文并创建、修改、替代或取消事件的指令。

事件日志只记录事实，不直接执行自然语言。效果配置只引用稳定ID，不按显示名分支。任一子事件保存：

```text
eventId
eventType
status
rootEventId
parentEventId
causedByEventId
sourceRef
controllerRef
subjectRefs[]
targetRefs[]
payload
tags[]
createdAtSequence
```

`status`至少为`proposed | committed | resolving | resolved | prevented | cancelled | replaced`。请求型事件先是`proposed`，通过合法性、替代和费用后才`committed`；已经`committed`的攻击不会因来源随后死亡而自动取消。

## 二、对象、引用与区域

### 2.1 对象种类

`game`、`ruleset`、`team`、`player`、`character`、`cardTemplate`、`cardInstance`、`ability`、`effectInstance`、`attack`、`damageSegment`、`status`、`marker`、`counter`、`duration`、`choice`、`responseWindow`、`judgment`、`zone`。

### 2.2 引用

所有引用使用`{ kind, id }`，临时对象可使用`$source`、`$controller`、`$subject`、`$target`、`$event`、`$attack`、`$damage`、`$card`、`$choice`等上下文引用。跨事件取值必须显式引用`eventId`或保存的变量，禁止依赖隐式“上一项”。

### 2.3 区域

`drawPile`、`discardPile`、`hand`、`resolving`、`judgment`、`weaponSlot`、`thirdWeaponSlot`、`armorSlot`、`mountOffenseSlot`、`mountDefenseSlot`、`talentZone`、`bossSlot`、`outsideDeck`、`removedFromGame`。

区域移动必须带`moveKind`：

`draw`、`play`、`use`、`respond`、`discard`、`lose`、`gain`、`give`、`equip`、`replace`、`dismantle`、`synthesizeConsume`、`transform`、`reveal`、`judge`、`return`、`remove`、`systemMove`。

同一物理移动可同时产生上层语义事件，但不能互相冒充。例如合成材料是`lose + synthesizeConsume`，不是`discard`；拆除是`dismantle`并通常以移动至弃牌堆收尾。

## 三、完整时间轴与时间点

### 3.1 对局

`game.setup.before` → `game.setup` → `game.setup.after` → `game.start` → 回合循环 → `game.victory.check` → `game.end.before` → `game.end`。

初始化内部顺序：载入规则包→建立座位/队伍→选择角色→创建牌实例→洗牌→发初始手牌→建立角色属性/初始天赋→确定首个回合。

### 3.2 轮与回合

对叙述主体而言，轮边界是其相邻两个准备阶段开始之间。回合时间点：

`turn.before` → `turn.start` → 六阶段 → `turn.end.before` → `turn.end` → `turn.after`。

若玩家淘汰则不创建后续回合。静滞等“跳过回合”仍创建回合壳及结束阶段，但其他阶段分别产生`phase.skip`。

### 3.3 阶段

标准阶段ID及顺序：

1. `prepare`
2. `judgment`
3. `draw`
4. `play`
5. `discard`
6. `end`

每个阶段统一具有：

`phase.before` → 替代/跳过检查 → `phase.start` → `phase.body` → `phase.end.before` → `phase.end` → `phase.after`。

- `phase.before`对应“即将进入阶段”，阶段即使之后被跳过也可能触发；
- 被跳过时产生`phase.skip`，不产生该阶段的`start/body/end.before/end`，随后产生`phase.after`；
- 被替换时产生`phase.replace`，执行替代流程，不执行原阶段正文，随后产生`phase.after`；
- “阶段刚结束后”挂在`phase.after`，因此明确写即使阶段被跳过仍触发的效果也可监听带`skipped=true`的`phase.after`。

### 3.4 主动动作

所有主动动作统一：

`action.declare` → `action.legality.check` → `action.targets.choose` → `action.costs.calculate` → `action.costs.pay` → `action.commit` → `action.resolve.before` → `action.resolve` → `action.resolve.after`。

失败边界：

- 合法性失败：`action.illegal`，不支付；
- 选择取消：`action.cancelled`，不支付；
- 支付失败：`action.payment.failed`，不提交；
- 提交后被无效：产生`action.invalidated`，已付费用不退，是否创建后续对象由无效节点决定。

装备、合成、技能、蓄力、攻击、主动弃装备、使用卡牌均是`action`的子类。

### 3.5 卡牌使用

`card.use.declare` → 移入结算区 → 选择/费用 → `card.use.committed` → 响应窗口 → `card.effect.before` → `card.effect.resolve` → `card.effect.after` → 离场。

另有独立事件：`card.played`、`card.responded`、`card.equipped`、`card.lost`、`card.discarded`、`card.gained`、`card.given`、`card.dismantled`、`card.replaced`、`card.transformed`、`card.synthesized`。一个操作可以合法产生多个事件。

### 3.6 攻击

标准攻击时间轴：

1. `attack.declare`
2. `attack.weapon.resolve`：读取预选有效武器/手刀及主动方式
3. `attack.targets.choose`
4. `attack.legality.check`：目标、距离、次数、杀及其他条件
5. `attack.costs.calculate`
6. `attack.costs.pay`
7. `attack.killInvalidation.check`
8. `attack.commit`：攻击正式发起；蓄力在此清零，号角在此消耗
9. `attack.targeted`：逐目标“指定目标后”
10. `attack.response.before`
11. `response.window.open`
12. 响应权循环及响应栈
13. `response.window.close`
14. `attack.hit.determine`
15. `attack.hit`或`attack.miss`
16. 逐伤害段结算
17. `attack.target.after`
18. 立即完成该目标濒死
19. 逆时针继续下一目标
20. `attack.after`
21. `attack.resolved`

【杀】被盾牌、圆盾无效发生在`killInvalidation.check`，攻击尚未`commit`；鲜血诅咒是支付后、无效检查前创建的特殊“目标已合法指定”效果。多目标按目标完整串行，不先统一扣血。

### 3.7 响应

响应窗口具有`windowType`、`eligiblePlayers`、`priorityOrder`、`allowedResponses`、`passState`：

- 普通攻击响应：目标依次获得出闪、防具、技能闪、近战格挡等权利；
- 判定干预：从当前回合玩家逆时针，任一干预后重新开放一轮；
- 效果响应：明确响应另一个效果时后进先出；
- 特殊出牌请求：先按指定顺序收集所有结果，再结算后果，不是攻击响应；
- 濒死救援：按濒死流程开放药水、号角及合法技能。

事件：`response.window.opened`、`response.priority.granted`、`response.declared`、`response.committed`、`response.resolved`、`response.passed`、`response.round.reopened`、`response.window.closed`。

### 3.8 判定

`judgment.requested` → 从真实牌堆取得牌 → `judgment.card.revealed` → 干预窗口 → 可重复`judgment.replaced` → `judgment.finalized` → `judgment.matched`/`judgment.notMatched` → 判定牌离场。

替换时原判定牌先弃置，再翻开新牌并重新开放干预。颜色判定必须携带`purpose`，例如`critical`、`status`、`branch`、`additionalEffect`；只有`purpose=critical`或正文明确指定时才构成暴击。

### 3.9 伤害段

每个伤害段必须独立创建：

1. `damage.proposed`
2. `damage.immunity.check`
3. `damage.replacement.before`
4. 箱子/陷阱箱等优先拦截
5. 普通增减与铁盾；真实伤害跳过相应层
6. 特殊生命层/蓝盾/护盾/血量路由
7. `damage.finalized`
8. 正数或死亡未淘汰特例产生`damage.received`
9. `damage.applied`
10. 分别记录`shieldLost`、`hpLost`、`specialLayerLost`
11. `shield.broken`、伤害后触发
12. `damage.after`

必须分别保存：

- `hit=true`：攻击命中；
- `receivedEvent=true`：目标收到伤害事实；
- `actualDamage`：实际扣除的总量；
- `actualHpLoss`：实际扣除血量；
- `actualShieldLoss`：实际扣除护盾。

普通0伤不产生`damage.received`；死亡未淘汰且无血盾条是明确特例：产生`damage.received`，但三个实际扣除值均为0。

伤害`deliveryType`为`attack | direct`；`attackType`为`melee | ranged | laser | field | none`；`damageType`为`normal | hp | shield | true | modify`；元素标签为`fire | poison | electric | ice | none`。附加伤害以`isAdditional=true`标识，不能靠父子层级猜测。

### 3.10 濒死、死亡、淘汰与胜负

每个可能令血量≤0的结算后立即：

`dying.check` → `dying.enter` → 救援窗口 → 重复检查 → `dying.rescued`或`death.before` → `death` → 死亡替代 → `elimination.before` → `elimination` → `victory.check`。

濒死中产生新濒死时，新濒死流程压栈优先完成。死亡不必等于淘汰；钢铁破浪者号以`deathReplacement`阻止淘汰。已经创建的攻击、伤害、延时效果不因来源死亡自动取消。

## 五、效果操作全集

### 5.1 控制流

`sequence`、`forEach`、`if`、`switch`、`repeat`、`whileBounded`、`break`、`continue`、`return`、`noop`、`setVar`、`assert`。

流程级操作另有`skipPhase`、`replacePhase`、`endPhase`、`checkVictory`、`setPresenceState`和`eliminateCharacter`；这些操作只能创建相应事件，不能直接静默跳改状态。

所有循环必须有静态或配置上限。反弹、传递等理论循环还必须有`chainDepth`上限；当前通用安全上限为10，具体规则可更低。

### 5.2 选择与随机

`requestChoice`、`selectTargets`、`selectCards`、`selectOption`、`selectNumber`、`selectColor`、`selectWeaponMode`、`randomChoice`、`shuffle`。

选择必须声明：

`chooser`、`min`、`max`、`distinct`、`selector`、`visibility`、`optional`、`timeoutPolicy`、`revalidateAtCommit`。

隐藏手牌选择使用`visibility=cardBackOnly`并由服务端随机排列候选，不能把正面身份发送给选择者。

### 5.3 数值与属性

`calculate`、`setValue`、`modifyValue`、`clampValue`、`payValue`、`recoverHp`、`recoverShield`、`changeHp`、`changeShield`、`changeMaxHp`、`changeMaxShield`、`modifyIronShield`、`modifyHandLimit`、`modifyAttackCount`、`modifyDistance`。

恢复、修改、支付和伤害是不同操作。`changeHp`不会自动套用伤害/无敌流程；`payValue`失败不能提交动作。

### 5.4 卡牌与区域

`createCard`、`copyCard`、`moveCard`、`drawCards`、`revealCards`、`displayCards`、`searchCards`、`shuffleDiscardIntoDeck`、`useCard`、`playCard`、`respondCard`、`discardCard`、`loseCard`、`gainCard`、`giveCard`、`equipCard`、`replaceEquipment`、`dismantleCard`、`synthesizeCards`、`transformCard`、`removeCard`。

### 5.5 攻击、响应、判定与伤害

`createAttack`、`invalidateAttack`、`setAttackTag`、`openResponseWindow`、`requestSpecialPlay`、`resolveHit`、`createDamage`、`modifyDamage`、`preventDamage`、`redirectDamage`、`judgeColor`、`replaceJudgment`、`applyCritical`、`checkDying`。

`createAttack`必须完整声明：

```text
source
controller
weaponRef/null
modeId
targets
targetOrder
range
attackTypes[]
costPolicy
responsePolicy
damageSegments[]
onTargeted[]
onHit[]
onMiss[]
afterTarget[]
afterAttack[]
```

每个`damageSegment`声明：

```text
segmentId
deliveryType
attackType
damageType
element
amount
repeat
isAdditional
ignores[]
overflowPolicy
```

### 5.6 状态、标记、次数与持续期

`applyStatus`、`refreshStatus`、`stackStatus`、`removeStatus`、`applyRestriction`、`removeRestriction`、`addMarker`、`modifyMarker`、`consumeMarker`、`resetMarker`、`consumeLimit`、`resetLimit`、`startCooldown`、`tickCooldown`、`createDuration`、`expireDuration`、`createSpecialLayer`、`removeSpecialLayer`、`enableAbility`、`disableAbility`、`enableEquipmentEffects`、`disableEquipmentEffects`、`scheduleEffect`、`cancelScheduledEffect`。

状态必须声明`stackPolicy`：

`uniqueRefresh | uniqueIgnore | stackCount | stackInstances | replaceByPriority`。

冰冻、电击使用`uniqueRefresh`；多个圆盾属于不同来源的`stackInstances`。

### 5.7 事件控制

`emitEvent`、`listenEvent`、`replaceEvent`、`cancelEvent`、`preventEvent`、`modifyEvent`、`enqueueTrigger`、`openTriggerWindow`。

只有仍为`proposed`的事件可被`replaceEvent`；已提交事件只能由明文效果创建后续抵消、无效或修改事件，不能篡改历史日志。

## 六、表达式与选择器

### 6.1 表达式

支持字面量、引用、变量和纯函数：

`add`、`sub`、`mul`、`divFloor`、`min`、`max`、`clamp`、`count`、`sum`、`coalesce`、`and`、`or`、`not`、`eq`、`ne`、`lt`、`lte`、`gt`、`gte`、`in`、`hasTag`、`exists`。

表达式不得产生副作用。所有随机必须通过显式随机操作并写事件日志。

### 6.2 通用选择器

角色过滤维度：

`inPlay`、`notEliminated`、`notLeftPlay`、`alive`、`dead`、`self/other`、`ally/enemy`、`withinRange`、`seatOrder`、`hasStatus`、`hasCard`。

卡牌过滤维度：

`zone`、`owner`、`controller`、`category`、`subtype`、`color`、`templateId`、`printedColor`、`effective`、`equipped`、`public`、`dismantlable`、`discardable`。

“在场”不得用`alive`代替；死亡未淘汰和超界者离场必须分别通过状态字段判断。

## 七、触发器、替代与优先级

触发器结构：

```text
triggerId
listen.eventType
listen.timing
filter
controller
mandatory
limit
priority
effects[]
```

同窗规则：

1. 替代/防止类先处理，按明文优先级及依赖排序；
2. 同一角色多个普通触发由该角色选择；
3. 不同角色从当前回合玩家逆时针；
4. 明确响应使用响应栈，后进先出；
5. 多目标不是“同时”，按目标逆时针完整串行。

优先级数值只用于系统层：

`legality(1000)`、`replacement(900)`、`prevention(800)`、`mandatoryModifier(700)`、`optionalModifier(600)`、`ordinaryTrigger(500)`、`cleanup(100)`。卡牌不得通过随意填写数值越权，应引用命名级别。

## 八、持续期模型

持续实例必须保存：

```text
durationId
sourceRef
ownerRef
anchorEventId
activationPoint
expiryPoint
remainingCount
countScope
skipPolicy
sourceLeavePolicy
ownerEliminatedPolicy
cleanupEffects[]
```

可用到期点：

- `currentTurn.end`
- `owner.nextTurn.before/start/end`
- `owner.nextPhase.<phase>.before/start/end/after`
- `owner.nthTurn.<n>.<point>`
- `target.nextPhase.<phase>.<point>`
- `round.endForOwner`
- `event.after`
- `condition.met`
- `permanent`

“到准备阶段前”统一编码为该准备阶段`phase.before`之前的到期事件；“准备阶段开始前触发”监听`phase.before`。跳过策略必须显式：

`expireOnSkippedBoundary | waitForActualPhase | ignoreSkip | fireAtAfterEvenIfSkipped`。

## 九、次数、CD、蓄力与作用域

次数作用域：

`perAction`、`perAttack`、`perTargetPerAttack`、`perDamageSegment`、`perTurnOwner`、`perTurnAny`、`perRoundOwner`、`perOffTurnWindow`、`perGame`。

次数只在规定的`consumeOn`事件消耗，例如号角在`attack.commit`消耗，精致法杖在首次`attack.hit`即使最终0伤也消耗。

CD=N记录`readyAfterOwnerRoundCount=N+1`，在拥有者准备阶段判断。蓄力保存于武器实例；装备区间转移保留，进入手牌/弃牌/牌堆清零，装备失效不清零，`attack.commit`清零。

## 十、超时、隐藏信息与确定性

- `pass`：有利、可选发动；
- `randomLegal`：强制或不利选择；
- `useDefault`：正文给定固定默认；
- `abortRemaining`：暗黑大骑士最后一击等停止后续可选序列。

随机选择、洗牌和隐藏候选排列由服务器随机源产生并记录`randomResultId`。客户端只收到按权限过滤的视图。回放必须能仅凭初始随机种子、玩家指令和版本包重建。

## 十一、DSL示例

冰冻：

```json
{
  "op": "applyStatus",
  "target": "$target",
  "params": {
    "statusId": "status.frozen",
    "stackPolicy": "uniqueRefresh"
  },
  "expiry": {
    "point": "target.nextPhase.play.after",
    "skipPolicy": "expireOnSkippedBoundary"
  }
}
```

近战格挡整次远程攻击：

```json
{
  "op": "invalidateAttack",
  "params": {
    "attack": "$attack",
    "condition": {
      "and": [
        { "hasTag": ["$attack", "ranged"] },
        { "not": { "hasTag": ["$attack", "cannotMeleeBlock"] } }
      ]
    },
    "result": "miss"
  }
}
```

多目标逐个完整结算：

```json
{
  "op": "forEach",
  "params": {
    "items": { "selector": "attack.targets.counterclockwise" },
    "mode": "serial"
  },
  "effects": [
```
