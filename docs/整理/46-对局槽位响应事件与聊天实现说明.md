# 对局槽位、响应、事件与聊天实现说明

## 一、实现范围

客户端对局投影现已明确展示武器1、武器2、第三武器、防具、进攻坐骑、防御坐骑、天赋、BOSS及判定区。`equipment`仍只作兼容字段；新界面不再从笼统装备数组推断槽位、空槽或手刀合法性。

本地武器预选只接受服务器在`preselectableWeaponSlots`中列出的槽位。空槽可被服务器声明为可预选；客户端不自行判断“所有武器槽为空”或手刀是否有效。

## 二、响应与选择

- 响应横幅显示当前优先座位、是否强制、响应类型、超时策略和按服务器时间估算的倒计时。
- 七种选择类型均由`SelectionSpec`驱动；卡牌与目标的多选顺序按点击顺序保存并显示编号。
- 所有高亮、失效提示、可选目标与空槽可选性均来自服务器投影。
- 提交时复制普通选择值，不克隆Vue响应式代理；新修订或切换报价会清空旧选择。

## 三、表现事件和聊天

客户端消费严格的表现事件队列，显示攻击、判定、伤害、濒死、死亡等关键事件及强调层；事件只负责演出，不反推权威状态。对局内提供“全部”和“队伍”聊天，发送内容仍通过正式游戏命令进入服务器。

协议Schema现有43个定义、86个内部引用。`PlayerView`、`PrivateView`与`PromptView`已补齐明确槽位、判定区、私密预选和超时语义。

## 四、验收

- 浏览器实测：四方座位按观看者旋转；仓库角色和卡牌图片成功渲染；空武器槽预选常亮；详情抽屉可打开；合法卡牌与目标可提交；服务器事件回显进入日志；全局聊天可发送并显示。
- `npm run build`通过，生产构建61模块。
- `npm test`通过：3个测试文件、10项测试。
- 客户端协议、协议正反例及权威引擎契约三套校验均通过。
