# 回合与六阶段时间轴实现说明

## 一、稳定边界

权威状态新增`phaseBoundary=body|after`和`phaseMode=automatic|manual`。服务器只在阶段正文或跳过/替换后的完成边界接受下一次推进，不把尚未完成的`phase.before/start/end`中间态暴露为玩家操作状态。

普通推进严格产生：旧阶段`end.before→end→after`，再进入新阶段`before→start→body`。出牌、弃牌标记为手动阶段，其余阶段标记为自动阶段；标记只描述调度需求，具体回盾、判定、摸牌和弃牌效果尚未在本层执行。

## 二、跳过与替换

下一阶段可声明`normal|skip|replace`。跳过产生`phase.before→phase.skip→phase.after`，不产生`start/body/end`；替换产生`phase.before→phase.replace→phase.after`，同样不执行原阶段正文。下一次推进从`after`直接进入后续阶段，避免为未发生的阶段伪造结束事件。

## 三、回合切换

结束阶段完成后产生`turn.end.before→turn.end→turn.after`，随后按1→2→3→4逆时针寻找下一名未淘汰玩家，产生其`turn.before→turn.start`并进入准备阶段。跨过本局首座时轮次数递增，即使首座本人已淘汰也不会导致轮次数停滞。

存在提示窗口、结算栈或濒死栈时拒绝推进，防止时间轴越过尚未完成的规则结算。

## 四、验证

- 服务端7个测试文件、25项测试及TypeScript构建通过。
- 覆盖六阶段顺序、手动/自动标记、跳过事件缺失要求、跳过后的继续推进、淘汰玩家跳过、跨首座轮次增长和不稳定窗口拒绝。
- 引擎契约及冻结规则包继续通过。

下一步实现阶段正文调度器，先接准备阶段基础回盾/破盾标记与摸牌阶段通用摸牌，再建立手动阶段报价边界。
