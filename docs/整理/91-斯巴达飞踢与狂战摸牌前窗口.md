# 斯巴达飞踢与狂战摸牌前窗口

状态：服务端R008、R047实现记录。

## 一、斯巴达飞踢

枭首者进入自己弃牌阶段正文时，即使当前不需因手牌上限弃牌，只要手中至少有1张牌，仍会保留弃牌阶段操作窗口并报价斯巴达飞踢。

提交时重验使用者、阶段、所有手牌实例及在场目标；必须弃置当时全部手牌且不得重复。付费后按手牌数通过统一直接伤害管线造成护盾伤害。

“本次令目标破盾”严格定义为：本次前目标护盾为正，结算后变为0。符合时给枭首者本人的下一次摸牌数-1；否则给目标下一次摸牌数-1。每次飞踢产生独立修正实例，可与同源或其他来源叠加，在受影响角色下一个摸牌阶段完成或被跳过后消耗。

## 二、狂战宣告

狂战士的摸牌阶段未被跳过时，在任何实际摸牌前开放可选窗口。选项`0/1/2`从冻结`character-rules.json`读取；超时按可选有利操作规则选`0`。窗口解决前不会抽牌。

选择1或2时，以单次摸牌修正进入统一数量管线，因此会在其他修正全部合并后才将实际数量钳制为0。同时产生一个只适用于武器攻击、在第一次正式`attack.commit`时消耗、当前回合结束到期的必定暴击授权。杀在攻击提交前被盾牌/圆盾无效时不会消耗。选择2还使当前可攻击次数+1。

选择命令校验对局、修订、优先权、提示和报价，并保存幂等结果。选择后自动调度器会重新进入同一摸牌阶段正文，但通过阶段内已解决标记防止重复开窗；抽牌后立即清除该标记。

## 三、验证

测试覆盖无强制弃牌时仍保留飞踢窗口、全手费用、破盾/未破盾分支、部分支付零污染拒绝、狂战选择2的少摸/次数/必暴、超时放弃和幂等。服务端53个测试文件、228项测试及TypeScript构建全部通过。
