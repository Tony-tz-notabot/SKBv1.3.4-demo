# 阶段一注册表与窗口执行验收

## 一、用途

本文记录“真实可玩链路 Goal”阶段一的验收证据。阶段一范围是：

- `playRegistry.ts` 代表性真实出牌链路；
- 从真实 `PendingWindowState` 生产点反向建立的窗口覆盖矩阵；
- 缺失的 `windowRegistry` 适配与超时补齐；
- 投影选择规格和隐藏信息隐私测试。

阶段一不宣布完整可玩，也不覆盖武器 W01—W66 总验收和跨规则组合冲突审计。

## 二、已验收证据

### 2.1 出牌注册表

`server/src/app/playRegistry.test.ts` 已覆盖 8 条真实链路：

- 手刀攻击；
- 武器攻击；
- 药水回复；
- 武器装备；
- 主动丢弃装备；
- 武器合成；
- 炼金术士剧毒药剂；
- stale revision 与非法选择零污染。

每条链路都经过真实 `GameService`、服务器报价、`GAME_SNAPSHOT` 协议校验、同 `commandId` 幂等和执行后新投影。

### 2.3 本轮补齐

`windowRegistry.ts` 新增：

- `redLordSealingHammer` → `RedLordHammerSession`；
- `statueCardSelection`、`statuePaladinResponse`、`statuePriestTake`、`statueKnightDuel`、`statueKnightWeapon` → `StatueChoiceSession`。

`buildWindowCommand` 新增 `meleeTargetRef`/`laserTargetRef` 映射，支持红爵士封灵战锤的两个独立目标组。

`projection.ts` 新增：

- 红爵士激活报价的两个可选目标规格（`meleeTarget`、`laserTarget`，min 0 / max 1）；
- 雕像隐藏候选改为 `concealed:` 占位符，不再把目标手牌牌面身份放进选择者报价；
- `resolveWindowSelectionValues` 把客户端 `concealed:` 引用还原为服务端内部卡牌引用。

`statueCardSelection` 超时使用权威随机源从合法报价中选取，并写入 `randomHistory`。

### 2.4 客户端

`client/src/views/GameView.vue` 与 `client/src/styles/base.css` 支持：

- 多目标规格（红爵士近战/激光独立选择）；
- 隐藏候选占位符点击后直接提交对应服务器报价；
- 隐藏候选合法/选中状态和选择顺序展示。

## 四、阶段一剩余边界

阶段一已经建立注册表与窗口适配的验收骨架，但以下内容仍不属于“完整可玩”：

- 注册表每个 entry 尚未全部逐项端到端验收；
- 所有可达窗口的 app 层超时测试尚未形成逐 kind 全覆盖；
- 未卜先知等私人展示卡在选择规格中已隔离给拥有者，但客户端私有展示区仍待后续实现；
- 身份认证、持久化幂等、观战投影、演示事件广播、静态托管和四人建房到胜负 E2E 仍留待后续阶段。
