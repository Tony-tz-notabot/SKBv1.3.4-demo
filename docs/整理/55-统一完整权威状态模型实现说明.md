# 统一完整权威状态模型实现说明

## 一、结果

服务端现只有一个根状态类型`AuthoritativeGameState`。原`SetupGameState`已删除，不再让开局与正式对局各自维护一套牌堆、手牌和修订信息。开局创建函数直接返回统一状态，重摸事务、命令边界和受众投影全部消费该状态。

统一状态包含：

- 身份、规则版本、修订号、事件序号、生命周期和胜方；
- 四座用户、队伍、角色身份、在场/生命状态、血盾、铁盾、状态、标记和额度；
- 全部卡牌实例及规范化区域；
- 开局重摸状态、正式回合/阶段、当前窗口；
- 结算栈、攻击/目标/响应/伤害/濒死上下文；
- 持续实例、延时效果、随机历史、私人武器预选和领域事件历史。

## 二、区域单一来源

牌堆、弃牌、四座手牌、结算区、判定区、各装备槽、牌库外和移出游戏区统一存放在`zones`。卡牌实例只保存所属`zoneRef`作为反向引用，不再保留`drawPile/discardPile/hands`并行数组。查询手牌使用纯读取帮助函数，移动仍必须同时原子更新区域顺序和卡牌反向引用。

开局已经创建所有标准区域，包括每座手牌、判定、三个常规武器槽、第三武器、防具、双坐骑、天赋和BOSS槽。正式对局不需要在另一模型中重新创建卡牌。

## 三、生命周期

- `setupRedraw`：`round=0`、`activeSeat=null`、`phase=null`，四个未决定座位各有一个私密重摸窗口。
- 某座决定后，同一事务修改其`decided/used`并移除对应窗口。
- 四座完成后切换为`inProgress`，设置`round=1`、首座为`activeSeat`、`phase=prepare`并产生`game.start`。
- `ended`要求存在胜方；正式结束流程将在胜负执行器阶段接入。

## 四、不变量验证

`validateAuthoritativeState`会在创建和每次开局事务提交后验证：

1. 恰有四个唯一座位和四个唯一用户；
2. 每座拥有唯一合法手牌区；
3. 每张卡恰好出现于一个区域；
4. 区域中的卡牌与卡牌`zoneRef`严格互相对应；
5. 提示窗口ID不重复；
6. 开局决定状态与私密窗口一一对应；
7. 生命周期与轮次、行动座位、阶段和胜方一致；
8. 领域事件连续，且不超前于当前修订/事件序号。

任何不变量失败均抛出稳定`StateInvariantError.code`，事务结果不能进入后续投影或持久化。

## 五、验证

- 服务端TypeScript构建通过。
- 服务端5个测试文件、19项测试通过，其中新增重复区域卡牌和重摸窗口失配反例。
- 引擎契约扩展为21个定义、50个引用、5种操作并通过结构校验。
- 客户端协议、16项正反例和冻结规则包继续通过。
