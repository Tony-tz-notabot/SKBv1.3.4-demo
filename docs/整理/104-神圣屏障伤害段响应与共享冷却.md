# 神圣屏障伤害段响应与共享冷却

## 一、统一规则口径

- 神圣屏障有主动与伤害响应两个入口，共用同一个`CD=1`。
- 主动入口只在圣骑士自己的出牌阶段开放；支付2张蓝色牌后获得无敌，不追溯免疫既往伤害。
- 响应入口在圣骑士即将受到一个具体伤害次数时开放；支付相同费用，免疫当前伤害并立即获得无敌。
- 无敌免疫除修改血量/护盾外的一切伤害，包括真实伤害；持续到圣骑士下个准备阶段开始前。
- 放弃或超时不发动、不支付费用、不进入冷却。

## 二、费用区域

蓝色费用牌可来自手牌、武器位、第三武器位、防具位、两个坐骑位、天赋区或判定区。初始天赋不是卡牌实例，不能支付；BOSS牌受不可主动丢弃的专属限制，不进入合法集合。

支付时逐张进入弃牌堆。装备区实例离场会产生完整`card.lost`事实，因而可继续触发血箱等失去装备效果。

## 三、逐段伤害窗口

攻击伤害执行器在服务器自动调度模式下改为每次权威提交最多结算一个伤害次数：

1. 锁定当前段和重复序号；
2. 若神圣屏障合法，开放可选窗口；
3. 放弃后只标记本次已询问，恢复同一伤害次数；
4. 发动后支付费用、建立无敌，再恢复该伤害次数；
5. 完成后才进入下一伤害次数。

直接伤害的即时计划也在移除计划前执行同样检查。放弃标记保存在该计划效果上，防止恢复后重复询问；发动后由无敌阻止当前计划伤害。

保留了`resolveCurrentAttackTarget`的非交互批量调用模式，既有底层单元测试和内部纯结算调用不会被强制拆段；正式战斗调度明确启用逐段响应模式。

## 四、持续期与冷却

- 无敌创建独立状态与持续实例，到`owner.nextPhase.prepare.before`移除。
- 发动时冷却保存为还需经过2个自己的准备阶段；首次准备阶段移除无敌并将剩余次数降为1，第二次准备阶段降为0并重新可用。
- 主动和响应入口读取、写入同一冷却标记，不能分别使用。

## 五、验证

专项测试覆盖跨手牌/装备区支付、装备离场事件、主动只获得无敌、共享CD、准备前到期、逐个重复伤害窗口、放弃不耗额度、响应发动免疫当前段，以及攻击外直接伤害响应。服务端全量69个测试文件、300项测试通过，TypeScript生产构建通过。
