# 近战格挡响应与近反触发迁移

## 一、响应事实

`response.resolved`在近战武器格挡成功时记录响应角色、`meleeBlock`标签、攻击与目标。冻结触发筛选器新增通用`tag`匹配，不再由伤害执行器反查失手原因来识别近反。

## 二、近反执行

`talent.melee_counter`现由冻结定义匹配生效来源。匹配后复制被格挡攻击的规则快照，以近反控制者为新攻击来源、原攻击者为目标，不支付【杀】或攻击次数，并加入原攻击的`afterAttackQueue`，待原攻击完整结束后启动。

反弹攻击清除当前目标结算、判定结果、后续队列和旧限制使用键；保留武器、模式、攻击类型、响应与伤害定义。反弹深度继续统一限制为10。旧`damage.ts`中的`talent.melee_counter`专用判断已删除，道士未命中反弹仍保留其独立角色语义。

## 三、验证

真实远程攻击被近战武器格挡后，装备或初始近反通过冻结触发生成反弹；原攻击结算后新攻击进入原攻击者的响应窗口。服务端37个测试文件、164项测试及TypeScript构建全部通过。
