# 128-操作提示词系统设计（interaction-panel）

状态：设计稿，待实施。
关联：`docs/整理/00-规则整理索引.md`、`docs/整理/121-真实应用层与联机链路实现说明.md`、`docs/整理/123-阶段一注册表与窗口执行验收.md`。

## 1. 目标与范围

当前客户端**下方操作面板（interaction-panel）**的提示只由一个静态 `promptHints[kind]` 文案（`GameView.vue`）提供，只说明"你要做什么"，不说明操作的**完整效果与后果**（如攻击的伤害/距离、响应的后果），玩家无法据此决策。

本系统目标：让玩家在操作面板上能看懂——

1. **当前要做什么**（操作名与意图）；
2. **操作的实际效果**（伤害、距离、费用、目标数、附加效果等，数值来自服务器报价，随真实状态变化）；
3. **不操作的后果**（放弃/超时会发生什么）；
4. **可选范围**（合法目标、合法卡牌及数量约束）。

提示词数据一律来自**服务端投影**（`playOffer` / `windowOffer`），客户端只做文案渲染，不自行计算规则。

## 2. 提示层级

| 层级 | 位置 | 内容 | 数据源 |
|---|---|---|---|
| L1 面板提示 | interaction-panel 顶部 `.prompt-hint` | 操作意图 + 关键效果 + 不操作的后果 | 服务端窗口/报价上下文 → 客户端模板渲染 |
| L2 报价按钮 | `.offer-list .button` | 动作名 + 摘要（伤害/费用/目标数） | `offerLabel` + `offer.preview` |
| L3 选择器 | selection-checklist / 目标高亮 | 选择目的、可选范围、数量约束 | `selectionSpecs`（targets/cards/color/number/confirm） |

## 3. 每类操作的提示词内容规范

### 3.1 出牌阶段主动操作

**A1 攻击**（普通/武器/角色技能攻击；offer kind `attack`）
- 攻击类型（近战/激光）——`mode.attackTypes`
- 攻击距离（数字或"不限"）——`mode.range`
- 伤害预览：逐段「段数×单段伤害」，元素/伤害类型（普通/真实/感电/火/毒等）——`mode.damageSegments`
- 附加效果（破防、必暴、不可响应、不可格挡等）——`mode.responsePolicy` + 攻击标记
- 目标数与可选目标——`targetRule.min/max` + `legalTargetRefs`
- 费用（【杀】数量、攻击次数、需弃的牌）——`mode.costs`
- 后果提示（如"激光攻击不可近战格挡"）

**A2 使用手牌**（药水/号角/特殊牌）
- 牌名与效果摘要——`templateId` → 卡牌文案（含数值）
- 费用（弃牌/消耗）——offer 字段
- 可选目标与数量——`legalTargetRefs` + spec
- 后果（恢复量/增益/清除效果）

**A3 装备**（武器/防具/坐骑/天赋）
- 装备名、目标槽位——`preselectableWeaponSlots` / offer
- 效果摘要（攻击加成/防御/距离/天赋效果）
- 费用——`costs`
- 后果（替换旧装备、占用槽位、生效时机）

**A4 主动丢弃/拆除**
- 丢弃来源与数量——spec
- 后果（进弃牌堆、是否触发离场效果）

**A5 武器合成**
- 目标武器与所需材料（数量/牌色）——`synthesizeConsume`
- 合成结果摘要

**A6 角色主动技能**
- 技能名与效果（含数值）——`abilityId` → 文案
- 费用（怒气/牌/生命）——`costs`
- 目标/选择——spec
- 后果（伤害/控制/增益数值）

**A7 武器主动技/蓄力**
- 武器名、模式名——`modeIds/modeId`
- 效果与数值、当前蓄力进度/可用次数——`runtime.charge`

**A8 结束出牌阶段**
- 将进入的阶段（弃牌/结束）、手牌超限提醒——`handCount/handLimit`

### 3.2 响应类操作

**R1 响应攻击**（kind `attackResponse`）
- 攻击详情摘要：来源武器/角色、总伤害、距离、攻击类型——**需服务端在窗口 context 附带攻击快照**
- 各响应方式的实际效果：
  - 出【闪】→ 整次攻击未命中——`legalDodgeCardRefs`
  - 近战格挡 → 抵消整次近战攻击（激光不可格挡）——`legalMeleeBlockRefs`
  - 防具判定/防具挡牌 → 各自效果
  - 技能响应 → 效果
- 不响应的后果：将承受上述伤害并进入濒死判定

**R2 濒死救援**（kind `dyingRescue`）
- 当前血量（≤0）与伤害来源——`hp`
- 可用救援（药水/号角/技能）——`legalCardRefs`
- 放弃的后果（淘汰、队伍败北判定）

**R3 圣骑士响应**（kind `statuePaladinResponse`）
- 被阻止的雕像效果、阻止的代价

**R4 瓦尔基里响应**（kind `valkyrieBossResponse`）
- 可复制的对方 BOSS 及其效果、复制消耗

**R5 角色特殊响应**（网瘾/羊叫兽/超级大宝贝儿 dodge 类）
- 攻击详情（伤害/来源）——需 context 附带
- 出【闪】或放弃的后果（感电标记/伤害）

### 3.3 判定类操作

**J1 指定判定**（`judgmentDesignation`）
- 判定原因、可指定颜色及对应结果——`matchColors`
- 放弃 = 随机判定的后果

**J2 判定干预**（`judgmentIntervention`）
- 当前判定结果、可替换的牌、替换/放弃后果

**J3 判定确认**（`preJudgment`）
- 将要判定的内容与判定后效果

### 3.4 触发类操作

**T1 可选触发**（`optionalTrigger`）
- 触发效果名与效果（数值）——`abilityId` → 文案
- 发动/放弃后果

**T2 触发排序**（`triggerOrdering`）
- 参与排序的效果列表（各效果一句话）——context

**T3 触发选牌**（`triggerCardSelection`）
- 选牌目的（交付/展示/拆除）——context
- 可选范围与数量——`legalCardRefs` + min/max

### 3.5 选择类操作（通用）

**S1 选择目标**——目的（攻击/增益/拆除/转移）——offer kind + spec
**S2 选择卡牌**——目的与后果（拆除→弃置、交付→给谁、弃置→进弃牌堆）——spec
**S3 选择数值/颜色/模式**——每个选项的实际效果差异（如少摸1→下个攻击必暴）——spec 选项 → 效果映射（客户端本地表）
**S4 确认提交**——将执行的动作与效果摘要——confirm spec + offer preview

### 3.6 阶段类操作

**P1 弃牌阶段**（`discardPhaseAction`）——手牌数/上限、需弃数量——`handCount - handLimit`
**P2 开局重摸**（`initialRedraw`）——可重摸范围与次数（整手弃4摸4，仅一次）

### 3.7 BOSS/雕像类

**B1 BOSS 使用**——BOSS 名与效果、槽位占用、每回合限次
**B2 BOSS 后续效果**（扫射/轰击/扳手/追击等）——当前步骤与数值——context
**B3 雕像效果**（十类）——雕像类型与效果（治疗/拿牌/决斗等）——context

### 3.8 系统类

**SYS1 超时自动处理**——超时策略（pass/随机）与剩余时间——`deadlineAt - serverTime`
**SYS2 等待推进**——当前行动者与阶段——`activeSeat/phase`

## 4. 服务端投影缺口（实施清单）

1. **`playOffer.preview` 补充攻击摘要**：当前 `preview` 只有 `weaponRef/modeId/range/costSummary` 且 `costSummary=null`。需对 `kind:"attack"` 的报价补充 `damageSummary`（逐段字符串/结构化数组）、`range`、`costs`（杀数/次数/费用牌）。数据来自 `AttackOffer.source.mode`。
2. **`attackResponse` 窗口 context 附攻击快照**：`response.ts` 开窗时在 `context` 加 `attack:{sourceLabel, damageSegments, range, attackTypes}`（脱敏：只含公开信息）。
3. **BOSS/雕像/特殊窗口 context 补"目的"字段**：`context.purpose`（如 `dismantle/deliver/show/transfer`）供客户端生成 L3 选择器提示。
4. **schema 更新**：`InteractionOffer.preview` 增加 `damageSummary/range/costs` 可选字段；`AttackResponseContext` 增加攻击快照字段；重新生成 `shared` 类型并跑协议工具。

## 5. 客户端实施清单

1. `GameView.vue`：`promptHints` 静态表升级为「模板函数表」`promptRenderers[kind](snapshot)`，返回带数据的文案；L1 显示 `<p class="prompt-hint">{{ promptHint }}</p>`（已有容器）。
2. `offerLabel`：从 offer 数据生成 L2 摘要（动作名 + 伤害/费用）。
3. 攻击响应 L1：用 context 攻击快照生成"来源×伤害，距离X，不响应将承受…"文案。
4. 选择器 L3：按 `context.purpose` + spec 生成"为<目的>选择N张牌"。
5. 测试：`promptHints.test.ts`（L1 模板渲染攻击/响应/濒死/判定的动态数值）、`offerLabel` 扩展测试。

## 6. 验收口径

- 每类操作至少有一个 L1 模板；攻击/响应/濒死/判定四类必须展示**动态数值**（伤害/距离/血量/颜色）。
- 客户端不做规则计算：所有数值来自投影字段。
- 协议 schema 校验通过、两端构建与全量测试通过。
