# 账号登录体系与客户端视图修复

## 一、背景

此前身份基于浏览器 `localStorage` 自报 `userId`（`skb.userId`），同一浏览器多标签共享同一身份，无法一台电脑模拟四人。按用户要求改为**按账号密码算玩家**，便于一机四开联机测试。

## 二、服务端账号体系

### 2.1 存储与接口（`server/src/app/roomService.ts`）

- `accounts: Map<username, AppAccount>`，`AppAccount {username, userId, displayName, passwordSalt, passwordHash, createdAt}`（`types.ts`）。
- 持久化：`PersistedApplication.accounts`（`persistence.ts` 空状态与恢复已兼容 `accounts`）。
- `loginOrRegister(username, password, displayName?)`：
  - 用户名规范化（trim+小写），合法性 `/^[a-zA-Z0-9_\u4e00-\u9fa5]{2,20}$/`；
  - 账号不存在 → 自动注册（`scryptSync(password, salt=randomBytes(16).hex, 32)`，`timingSafeEqual` 校验）；
  - 账号存在 → 校验密码；错误返回 `ACCOUNT_PASSWORD_INVALID` / `USERNAME_INVALID`；
  - 成功后 `issueSession(userId, displayName)` 签发 token（沿用 `盐.密钥` 格式，存储 sha256，容量 2000）。
- `createSession(displayName)` 保留（旧测试/兼容），`resolveSession(token)` 兼容旧无盐 token。

### 2.2 HTTP 接口（`server/src/app/server.ts`）

`POST /api/session` body `{username, password, displayName?}` → 200 `{ok, userId, displayName, token, created}`；400 `USERNAME_PASSWORD_REQUIRED`；401 `ACCOUNT_PASSWORD_INVALID` / `USERNAME_INVALID`。

## 三、客户端登录面板（`client/src/App.vue`）

- 未登录显示登录卡片（账号+密码，自动注册说明，错误提示）；
- token 存 **sessionStorage**（每个标签页独立）——同一浏览器开 N 个标签页登录 N 个不同账号即可一机多开；
- 顶部显示当前账号 + 退出按钮（清除 sessionStorage 并 reload）；
- `?mock=1` 开发模拟不受影响；旧 `localStorage` 身份不再使用。

## 四、客户端视图优先级修复（重要）

`App.vue` 视图链原为「选角 > 房间 > 开局重摸 > 大厅 > 对局」，而 `roomProjection` 在 `phase="inGame"` 后**仍返回 ROOM_SNAPSHOT**，导致四人锁角后永远停在房间界面、开局重摸界面不出现（浏览器端 bug，协议层 E2E 不覆盖）。

修复后优先级：**GameView > SetupRedrawView > CharacterSelectionView > RoomView(phase!=='inGame') > LobbyView**。
