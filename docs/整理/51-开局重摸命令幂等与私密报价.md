# 开局重摸命令幂等与私密报价

## 一、命令校验顺序

`SetupCommandSession`按固定顺序处理重摸命令：`commandId`幂等结果→gameId→`expectedStateRevision`→生命周期→用户座位→是否已决定→`promptId/offerId`→原子执行。拒绝不改变状态；同一`commandId`无论之后载荷如何变化，都返回首次结果且不重复执行。

## 二、私密报价

未决定的玩家只收到自己的`resolveChoice`报价，包含固定的确认/放弃选项及`timeoutPolicy=pass`。其他玩家、观战者和已完成决定者看不到该报价；报价ID绑定具体座位，不能跨用户使用。

## 三、超时

超时处理复用同一命令入口，以服务器生成的命令ID提交`redraw=false`。因此超时同样经过修订、窗口、身份和幂等检查，不存在另一条绕过规则的修改路径。

## 四、验证

服务器现有4个测试文件、13项测试通过。新增覆盖：私密报价隔离、重复命令不重复重摸、过期修订、陌生用户、过期报价、拒绝零状态变化和超时自动保留原手牌。
