武器总览文末写“武器总数 67 张”，但与逐条数量不符；其五个颜色的标称数量、列出的编号数量也不能互相吻合，不能作为牌库初始化依据。

## 三、0 张与牌库外产物

目前明确不直接加入初始牌堆的内容至少包括：

- 武器：风魔手里剑、爆炸战锤、极光、妙妙枪、光剑土豪金、光剑紫、一拳（白）、重铸的圣剑、雪狐玫瑰金等标注为 0 张的武器；
- 防具：陷阱箱；
- 特殊牌：羊叫兽。

必须为每张 0 张牌补齐：

- 获得公式或生成来源；
- 使用后进入弃牌堆、移出游戏还是返回牌库外；
- 若进入弃牌堆，重洗时是否成为普通牌堆成员；
- 被重铸熔炉、搜索牌库等效果检索的资格；
- 对局开始时是否创建实例，还是合成时才创建实例。

正式规则：合成时创建实例；所有合成创建的产物实例离场后返回牌库外，不进入普通弃牌堆或重洗牌堆，除非牌面明确另行指定。

## 四、素材清单问题

- 实际目录名是 `assets`，UI 文档多处写成 `asset`，应统一为 `assets`。
- 规则有 66 种武器而图片只有 54 个，需生成逐项缺图表。
- 尚无坐骑、雕像、特殊牌独立素材目录。
- 缺少完整的牌背、槽位、技能、状态、攻击类型和元素图标体系。
- 同名 JPG/PNG、不同形态及候选角色图需要建立稳定资源键，不能由程序直接使用中文文件名猜测。

建议资源清单字段：

```text
resourceKey
category
entityId
variant
filePath
fallbackKey
width
height
checksum
licenseSource
```

## 五、机器可读牌库配置建议

牌库配置需要与规则版本绑定，示例结构：

```json
{
  "rulesetVersion": "1.3.4-draft.1",
  "cards": [
    {
      "templateId": "basic.kill.white",
      "count": 16,
      "initialZone": "DRAW_PILE"
    },
    {
      "templateId": "special.yang_jiao_shou",
      "count": 0,
      "initialZone": "OUTSIDE_GAME",
      "obtainBy": ["recipe.yang_jiao_shou"]
    }
  ]
}
```

注意：杀每色16、闪每色7、药水每色2、号角每色1；金币为白、红各1张，不要求五色均分。

所有卡牌数量、颜色及其他玩法参数均应从版本化规则配置读取，便于统一调节和测试，不得散落硬编码在业务逻辑中。

## 六、每张牌的统一字段

所有卡牌模板建议至少具有：

- `templateId`：稳定、永不因显示名改变而改变；
- 名称、类别、子类别、颜色、牌库数量；
- 使用区域、使用阶段、触发窗口；
- 费用与是否消耗攻击次数；
- 目标数量、目标限制、距离与射程；
- 是否创建攻击、攻击方式和响应限制；
- 伤害段数组；
- 判定、随机、展示和搜索行为；
- 持续期、状态和计数器；
- 装备槽、合成公式和离场去向；
- 正式规则文本、关键词和资源键；
- 规则版本与变更记录。

## 七、内容文档下一步

在 P0 裁定完成后，按以下顺序转换：

1. 基础牌、雕像、防具：数量较小，适合先验证模板。
2. 天赋、坐骑和特殊牌：验证持续效果、距离、合成和延时牌。
3. 武器：验证攻击方式、蓄力、多段和多形态。
4. 角色：验证技能窗口、专属状态和规则覆盖。
5. BOSS：最后验证复杂持续状态、特殊生命层和全场效果。
