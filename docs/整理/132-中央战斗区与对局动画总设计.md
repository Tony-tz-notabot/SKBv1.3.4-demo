# 132-中央战斗区与对局动画总设计

> 状态：**设计稿 v0（进行中）**。原始需求见 `docs/整理/131-中央战斗区大改原始需求记录.md`；已确认项见 `docs/整理/130-对局内动效设计稿.md`。
> 数据字段细节：本文 §2 的精确字段名由数据盘点子代理核实后回填（标注 ⏳ 处）；其余设计已定稿。
> 方法：**全部改动 TDD**（先红后绿），防止回归；每阶段以测试+构建为门禁。

## 1. 目标与范围

- R1/R5：移除原 `.game-center` 的牌堆/展示/弃牌静态三块，重做中央战斗区四子区：**主区、临时弃牌区、牌堆、弃牌堆**。
- R2-R4：**操作指示箭头**系统（作战地图风格宽箭头、自指环、多目标、无源箭头；状态机：白色荧光轮廓→实体化→按效果颜色能量流→目标动画；无效淡出；嵌套操作透明度降级）。
- R6：**摸牌动画**（中央牌堆/他人区域→角色区，所有人可见，按公开性正/背面）。
- R7：**判定/展示动画**（牌堆翻牌→主区；成功词条+卡牌高亮+边缘色光；失败变暗）。
- 整合 130 已确认项：血盾条 v1（细式、数值在左、主题提亮）、特殊状态图标行（条下装备区上，先文字芯片后图标）、对局内动效批次（A-I）。
- 服务端原则：**双流消费**——事件流（增量、按观众过滤）+ 快照（`publicView/privateView/interaction/activeWindow/log` 全量）。盘点结论：**纯客户端无法满足 R2-R7 核心需求**（命中/未命中、操作分组、进行中叙述、判定成败均缺结构化字段），须服务端投影层最小补齐（§2.4），引擎域事件尽量不动（仅 ⑦ 例外）。

## 2. 数据管线（事件源 → 操作组 → 舞台）

### 2.1 事件源

- 中央战斗区作为 GameView 子组件，**接收 `events` prop**（App.vue 已传、GameView 模板当前未用），组件内部维护"已消费 seq"，watch 增量喂给纯 TS 状态机（**不全局 watch eventQueue**——数组整体替换与快照重置竞争）。
- 事件序列单调去重沿用 `eventSeq`（serverProjection 已实现）；快照（GAME_SNAPSHOT）到达时重置状态机并丢弃陈旧事件。
- 已核实的 payload 字段（client-protocol.schema.json，2026-08 现场）：
  - `AttackDeclared`：`attackerSeat, targetRefs`；`AttackResolved`：`attackId, result`（**attackId 可用于操作组聚合**；声明侧无 attackId，需以 seq 区间+attackerSeat 关联 ⏳）
  - `DamageSegmentApplied`：`sourceRef, targetRef, segmentIndex, totalSegments, amount, hpLost, shieldLost`（能量流到达→目标伤害动画的数据）
  - `CardDrawn`：`seat, count, cardRefs?`（cardRefs 按观众可见性 ⏳）；`CardPlayed`：`seat, cardRef, purpose`；`CardDiscarded`：`seat, cardRef, reason`
  - `JudgmentRevealed`：`card, printedColor`（判定卡 ref+颜色公开 → R7 高亮色光数据）；`JudgmentResultChanged`：`from, to, reason`
  - `HealthChanged`：`seat, hp, shield, amount, change`；`ResponseResolved`：`responderSeat, result, cardRef`
- 客户端基建盘点结论（子代理核实）：日志渲染 `renderLogEntry`（summary，不用"你"）可直接复用为主区词条；`PromptSegment={text,cls}` 18 种 token 类可复用；**token 色系 CSS 作用域当前仅 `:is(.prompt-hint,.offer-preview,.game-log)`，主区词条需把新作用域（如 `.battle-narration`）追加进 base.css 相关选择器**。

### 2.2 操作组（Operation Group）聚合

- **定义**：一次"操作"= 从发起（如攻击声明/出牌/技能）到其因果链收束（响应、判定、伤害、后续触发）的完整序列。
- **聚合键（定稿）**：服务端新增**事件外层可选 `operationId`**（投影层把域事件 attackId/链 id 透传，横切 32 类，不动 payload oneOf）——这是操作组唯一可靠键。落地前客户端用启发式（`eventSeq` 邻近 + `attackerSeat`+`targetRef` 分叉）作临时聚合，标记为"best-effort"。
- **嵌套**：新操作在旧操作未结束时启动（如反击/连锁）→ 压入操作栈，旧操作箭头透明度降级（R4）。operationId 提供栈的入栈/出栈依据（嵌套者 operationId 不同或父子关系 ⏳ 由投影定义）。

### 2.3 主区词条（全员可见叙述）

- **双流互补**（盘点定稿）：
  - **进行中流**：`publicView.activeActivity`（服务端新增：当前操作摘要 `{kind, actorSeat, targetRefs, weaponRef?, …}`，补 activeWindow 在攻击结算期的空窗）——"正在发生什么"。
  - **已完成流**：`GAME_SNAPSHOT.log` 的 LogToken/LogEntryView（全员可见、已按观众过滤）——直接复用 `renderLogEntry` 渲染为词条（summary 模式，不用"你"）；缺口：summary 仅攻击有聚合行、数值在字符串内——精确数值由事件流（`DamageSegmentApplied.amount/hpLost/shieldLost`）补。
- **promptData 不可用于主区**（仅轮转玩家本人可见）。
- 词条 token 复用 128 三色系；**CSS 作用域需扩展**（`.battle-narration` 追加进 base.css 的 `:is(.prompt-hint,.offer-preview,.game-log)` 选择器）。
- 隐私：私密摸牌/弃牌折叠为数量词（`CARD_DRAWN` 他人仅见 `count`，本人见 `cardRefs`）；观战同公开视角。

### 2.4 服务端投影层最小补齐（定稿，M0 实施，全部 TDD）

盘点结论：**必须补齐**（否则 R2/R3 的"命中/未命中/无效"、R5 的"进行中叙述"、R7 的"判定成败"无数据）。改动均在**投影层 + schema + 生成类型 + presentationEvents 测试**，引擎域事件基本不动。

| # | 补齐项 | 内容 | 影响面 |
|---|---|---|---|
| ① | 事件外层 `operationId?` | 投影层透传域事件 attackId/链 id；横切全部演示事件 | PresentationEvent 外层 + 生成类型 + presentationFor + examples（**不动 payload oneOf**） |
| ③ | `ATTACK_RESOLVED` 补 `outcome` 枚举 + 每目标汇总 | `hit/miss/invalidated/cancelled` + `perTarget[]`（数据源：域事件 `attack.target.after.hit/actualHpLoss/actualShieldLoss`） | AttackResolvedPayload + projection + 测试 |
| ⑥ | `publicView.activeActivity` | 当前操作摘要（kind/actorSeat/targetRefs/weaponRef），全观众可见，补结算期空窗 | PublicView（additionalProperties:false 必须加字段）+ projection + 快照测试 |
| ⑦ | 修 `cards.given→CARD_DRAWN` seat 恒 1 缺陷；CARD_DRAWN 他人侧补 `concealed:draw:N` 占位 | 摸牌动画归属正确、牌背飞行有占位 | projection 一处 + 测试 |
| ②⑤ | （后置精确化）ATTACK_DECLARED 补 attackId/武器/伤害段；JUDGMENT_RESULT_CHANGED 补 judgmentId/判定卡 ref；DAMAGE_PREVENTED 补 preventedAmount/sourceRef | 更精确的声明信息与判定关联 | ④ 需碰引擎 damage.prevented 域事件——单独评审后实施 |
| ④ | 判定成败语义：客户端以 `JUDGMENT_REVEALED.card.printedColor` + 词条颜色映射先行（R7 高亮色光可用），成败精确结论待 ⑤/服务器语义字段 | — | — |

- 协议变更纪律：改 schema 后跑 `tools/validate-client-protocol.mjs`（+build 脚本重生成 shared 类型）、`presentationEvents.test.ts` 逐事件 Ajv 校验、全量服务端测试。

## 4. 操作指示箭头系统（R2）

### 4.1 几何规范（SVG）

- 形状：作战地图风**宽箭头**——整体宽；**尾部宽且中间自然凹陷**（尾部为浅凹 ∨ 形）；**主体左右两侧为外凸弧线**（类似弓形/彗尾）；**箭头大**（头部为宽角箭头，约占总长 30–38%）。
- 实现：单条 SVG path（无描边、纯填充），控制点由起点/终点/弯曲度参数化生成；`StageArrow.vue` 用 props 渲染。
- 参数（CSS 变量/组件 props，可调）：`--arrow-width`、`--arrow-curve`（弧度）、`--arrow-head-ratio`、`--arrow-tail-notch`。

### 4.2 形态

| 形态 | 说明 |
|---|---|
| 直线/弧线箭头 | 操作方→被操作方，起点在操作方面板边缘、终点在被操作方面板边缘 |
| 自指环 | 起点=终点（自己），箭头绕成一圈（环形路径，箭头头部贴近尾部起点），表示"自己对自己"的操作（如回血、蓄力、自伤） |
| 多目标 | 同一操作方对多个目标：从起点**扇形展开多根箭头**，各指向对应目标 |
| 无源箭头 | 一端无"源"：来自中央区（摸牌：牌堆→角色，牌堆端无尾部）或到中央区（判定/弃牌入堆：角色→中央，中央端无箭头头部）——用渐隐的"彗尾"表示无源端 |

### 4.3 状态机（R3，以攻击为例）

| 状态 | 渲染 | 触发（演示事件/快照字段） |
|---|---|---|
| `standby` | **仅白色系荧光轮廓**（无填充；白 `#eaf6ff` 描边 + `drop-shadow` 荧光） | `ATTACK_TARGETED`（选完目标）→ `RESPONSE_WINDOW_OPENED`（待响应） |
| `voided` | 淡出（opacity→0，≈400ms）后移除 | `ATTACK_RESOLVED.outcome=invalidated|cancelled`（③ 补齐后；此前用 result 字符串 `armor/status/invincible/meleeBlock` 等关键词兜底） |
| `solid` | 轮廓**实体化**（填充主题色/中性色出现，轮廓转实） | `ATTACK_RESOLVED.outcome=hit` 或无需响应直接命中 |
| `flow` | **尾部→头部能量流**：按效果类型着色的能量脉冲从尾向头移动（SVG `stroke-dashoffset`/移动渐变），**有冲击感**（发射时轻微挤压、到达时目标侧爆闪）；每段伤害一次脉冲 | `DAMAGE_SEGMENT_APPLIED`（`segmentIndex/totalSegments/amount/hpLost/shieldLost` 逐段） |
| `arrive` | 到达目标：触发目标对应动画（扣血/回复/获得牌等），随后淡出移除 | 脉冲到达头部；目标动画数据取 `DAMAGE_SEGMENT_APPLIED.hpLost/shieldLost`、`HEALTH_CHANGED` |

**效果→颜色映射**（复用 128 语义色）：血量伤害=红 `#ff8a7a`；护盾伤害=灰 `#9fb3bd`；回复=绿 `#6fdda0`；获得牌/摸牌=蓝 `#7fc4e8`；火=橙 `#ffb37a`；毒=绿深 `#3da86b`；电=黄 `#ffd27b`；冰=蓝 `#7fc4e8`；判定/无属性=白 `#eaf6ff`；费用/消耗=金 `#efd27b`。

### 4.4 嵌套操作（R4）

- 维护**操作栈**（深度）：新操作压栈 → 其箭头以全透明度渲染；旧操作（栈底）箭头 `opacity:.35` 降级（仍可见、不消失）；新操作处理完出栈 → 恢复原透明度继续旧操作。
- 入栈/出栈依据：`operationId`（① 补齐后）；临时聚合期用"同源连续事件中的操作类型切换"启发式（如反击的 RESPONSE→DAMAGE 链）。
- 栈深度上限（⏳ 初定 8，防失控）；栈变化本身可测试。

## 5. 主区词条（R5）

- 每条操作/步骤一行词条，置于主区顶部（或随主区牌并排），所有人可见。
- 句式（复用 128 模板思想）："`骑士` 用 `烈焰剑` 攻击 `圣骑士`（近战 1，火）：命中，护盾 -2" / "`萨满` 的判定：翻出 `红牌`——成功，施加 `电击`"。
- 词条构建为纯函数（输入：操作组事件序列 + 公开信息 → 输出：token 段数组），与 promptRenderers 同构，测试驱动。
- 隐私：私密部分折叠（"摸 2 张"），无后果/提示语气（体现对局，非提示操作）。

## 6. 摸牌与判定/展示动画（R6/R7）

- **摸牌**：`CARD_DRAWN`（本人见 `cardRefs`、他人/观战仅 `count`）→ 牌堆→目标角色区的飞行动画（沿无源箭头路径，彗尾起始于牌堆）；本人/公开见正面、他人见背面占位（`concealed:draw:N`，⑦ 补齐）；与 130 B1 手牌入场不冲突——中央飞行是"全场可见层"，手牌入场是"本人私密层"。
- **判定/展示**：`JUDGMENT_REVEALED.card`（**完整公开 CardView + printedColor**，全员可见）驱动翻牌动画（rotateY 90→0）进主区；判定卡高亮/变暗：先用 `printedColor` 映射边光颜色（红判定→红光，R7 可用），成败精确语义待 ⑤/服务器语义字段（当前以词条颜色映射先行）。
- 展示牌：`publicView.centralCards`（resolving 区 faceUp）与判定区 `PlayerView.judgmentZone` 均全员可见，作为主区牌流数据。
- 判定区/展示牌进入主区后随操作推进按序摊入临时弃牌区（R5 规则），操作组结束入弃牌堆。

- 状态机为**纯函数 reducer**（输入事件流+快照 → 输出舞台状态），动画只由 DOM/CSS 消费状态渲染——TDD 友好、可回放（同一事件流→同一舞台状态）。
- 事件源挂接：**CombatStage 收 `events` prop，内部维护"已消费 seq"**，watch 增量喂给状态机（不全局 watch eventQueue——数组整体替换与快照重置竞争）；GAME_SNAPSHOT 到达（stateRevision 变化）时重置状态机。
