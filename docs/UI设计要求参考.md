# 《Soul_Knight_Battle》线上版交互UI与房间联机设计方案

## 一、产品定位

《Soul_Knight_Battle》线上版是一款四人、二对二、回合制卡牌对战游戏。

游戏支持：

- 创建私人房间；
- 输入房间号加入；
- 房间密码；
- 四名玩家固定座位；
- 同一公网IP下多个不同账号同时游戏；
- 实时网络联机；
- 断线重连；
- 完整的服务器权威规则结算；
- 角色、卡牌、装备和状态的图像化展示；
- 对局日志与操作动画；
- 后续扩展观战、复盘与录像功能。

首发版本建议优先支持电脑网页端，同时适配手机横屏。

------

# 二、总体交互原则

## 2.1 服务器权威

客户端只提交玩家的操作意图，例如：

- 使用哪张牌；
- 使用哪把武器；
- 采用哪种攻击方式；
- 选择哪些目标；
- 是否发动技能；
- 是否进行响应；
- 是否结束当前阶段。

服务器负责验证并决定：

- 操作是否合法；
- 距离是否足够；
- 是否消耗攻击次数；
- 是否消耗【杀】；
- 是否可以响应；
- 判定结果；
- 伤害段结算；
- 铁盾、防具、护盾和血量的处理顺序；
- 濒死、死亡与淘汰；
- 胜负结果。

客户端不得自行修改血量、护盾、手牌、装备、牌堆或角色状态。

## 2.2 场面与日志分离

对局场面只显示：

- 当前使用的牌；
- 当前使用的武器；
- 当前技能；
- 当前判定牌；
- 当前攻击或效果目标；
- 当前操作的指示线；
- 当前正在结算的效果。

已经完成的操作不长期保留在中央区域，而是记录在独立的对局日志中。

## 2.3 短按与长按分离

所有角色、牌、装备和状态均支持查看详情。

统一交互规则：

- 短按：选择、切换或执行操作；
- 长按：打开详情面板；
- 拖动：只用于明确支持拖动的操作；
- 长按不得直接打出卡牌或发动技能。

电脑端可同时支持：

- 长按鼠标左键；
- 鼠标右键；
- 详情按钮。

手机端使用长按打开详情。

# 三、账号与同一IP多账号

玩家身份必须由账号信息识别，而不是由IP地址识别。

系统中的身份关系为：

```text
用户身份：user_id
登录会话：session_id
网络连接：connection_id
来源地址：ip_address
```

其中IP地址只用于：

- 安全审计；
- 登录和创建房间限流；
- 异常连接识别；
- 封禁辅助；
- 网络问题排查。

必须支持以下情况：

- 同一家庭网络中的四个玩家进入同一房间；
- 同一宿舍或校园网中的多个账号同时在线；
- 同一公网IP下多个游客账号；
- 同一公网IP下多个正式账号。

限制对象应当是账号和会话，而不是IP。

具体规则：

- 同一账号不能占据同一房间的两个座位；
- 同一账号只能拥有一个主对局连接；
- 同一账号在新设备登录时，可以接管旧连接；
- 同一IP允许多个不同账号进入同一房间；
- 不因同IP直接认定为作弊。

------

# 四、大厅与房间系统

## 4.1 游戏大厅

大厅提供三个主要入口：

- 创建房间；
- 输入房间号；
- 继续未完成的对局。

若玩家存在可恢复的对局，显示：

```text
继续对局
房间号：7KQ9MT
当前轮次：第4轮
当前状态：等待3号玩家响应
```

大厅还显示：

- 玩家昵称；
- 当前网络延迟；
- 规则版本；
- 卡牌图鉴；
- 角色图鉴；
- 设置；
- 退出登录。

## 4.2 创建房间

创建房间时可以设置：

- 房间名称；
- 房间密码；
- 是否允许游客；
- 是否允许观战；
- 回合时间；
- 响应时间；
- 备用时间；
- 使用的规则版本。

房间创建后，服务器生成六位房间号，例如：

```text
7KQ9MT
```

房间号排除容易混淆的字符：

```text
0、O、1、I、L
```

## 4.3 输入房间号加入

玩家输入六位房间号后，先显示房间预览：

```text
房间名称：SKB测试局
房主：Kurisu
人数：3 / 4
规则：标准规则
状态：等待准备
密码：需要
```

玩家确认后正式加入。

加入失败必须显示具体原因，例如：

- 房间号不存在；
- 房间已关闭；
- 房间人数已满；
- 密码错误；
- 对局已经开始；
- 房间不允许观战；
- 当前账号已在该房间；
- 账号被房主移除；
- 请求过于频繁。

# 五、房间准备界面

## 5.1 座位布局

四名玩家位置固定，不随本地玩家视角旋转。

```text
                    3号玩家
                       ●

          4号玩家 ●         ● 2号玩家

                       ●
                    1号玩家
```

回合和依次结算方向为逆时针：

```text
1号 → 2号 → 3号 → 4号 → 1号
```

对应屏幕方向：

```text
下方 → 右侧 → 上方 → 左侧 → 下方
```

队伍关系：

```text
A队：1号、4号
B队：2号、3号
```

可以在场面外围显示一条较淡的逆时针环形箭头，用来提示：

- 回合顺序；
- 多目标结算顺序；
- 传牌方向；
- 依次执行的效果方向。

## 5.2 玩家席位

每个席位显示：

- 座位号；
- 玩家昵称；
- 头像；
- 队伍；
- 房主标记；
- 网络延迟；
- 在线状态；
- 准备状态。

房主可以：

- 调整座位；
- 移除玩家；
- 修改房间设置；
- 转让房主；
- 开始游戏；
- 关闭房间。

开始游戏需要满足：

- 四个玩家席位均有人；
- 四名玩家全部准备；
- 所有玩家连接正常；
- 所有玩家使用同一规则版本。

------

# 六、角色选择界面

每名玩家获得四个私密角色选项。

其他玩家只能看到：

- 正在选择；
- 已经锁定。

不能看到：

- 对方获得的角色候选；
- 对方当前预选的角色；
- 对方最终选择的角色。

所有玩家确认后统一公开。

每张角色图像显示：

- 角色立绘；
- 角色名称；
- 初始血量；
- 初始护盾；
- 初始天赋图标；
- 技能图标；
- 操作难度。

长按角色立绘打开完整角色详情。

# 九、血量条与护盾条

## 9.1 血量条

血量条固定使用红色。

显示形式：

```text
HP  ███████░░░  5 / 7
```

血量减少时：

- 红色血条缩短；
- 显示伤害数字；
- 保留短暂的延迟残影；
- 角色播放受伤反馈；
- 详细结算写入日志。

血量恢复时：

- 红色血条增长；
- 显示恢复数字；
- 播放恢复反馈。

## 9.2 护盾条

护盾条固定使用灰色。

显示形式：

```text
SH  █████░░░░░  3 / 6
```

护盾减少时，灰色护盾条缩短。

护盾恢复时，灰色护盾条增长。

护盾为零并带有破盾标记时：

```text
SH  ░░░░░░░░░░  0 / 6
破盾
```

血量和护盾必须是两条独立的条，不能合并显示。

## 9.3 铁盾

铁盾使用独立数值图标：

```text
铁盾 +1
```

或：

```text
铁盾 -2
```

铁盾不属于可消耗生命条，因此不使用进度条。

## 9.4 特殊生命层

特殊生命层单独显示，例如：

- 大史莱姆临时血量；
- 工程师机甲护盾；
- 拳击柱额外血量；
- 特殊最低血量限制。

特殊生命层不能直接并入普通红色血量条或灰色护盾条。

# 十、装备区小图标

每名玩家面板中均显示完整装备区的小图标。

装备槽顺序为：

```text
武器1
武器2
第三武器
防具
进攻坐骑
防御坐骑
BOSS
初始天赋
天赋1
天赋2
天赋3
判定区
```

装备区槽位本身使用`asset`目录中提供的槽位图像。

前端不自行绘制最终槽位边框，也不把槽位样式硬编码在组件中。

建议资源键为：

```text
slot.weapon.primary
slot.weapon.secondary
slot.weapon.third
slot.armor
slot.mount.offensive
slot.mount.defensive
slot.boss
slot.talent.initial
slot.talent.normal
slot.judgment
```

当`asset`中加入正式槽位图片后，只需要修改资源映射，不需要修改界面逻辑。

## 10.1 武器图标

每把武器显示对应的图像资源。

武器图标上可以叠加：

- 当前攻击方式；
- 当前形态；
- 蓄力层数；
- 剩余耐久；
- 是否被选中；
- 是否处于失效状态。

例如：

```text
[火龙步枪图像]
方式Ⅱ
```

## 10.2 防具图标

防具图标显示：

- 防具图像；
- 剩余耐久；
- 当前触发状态；
- 是否失效。

例如箱子可以在右上角显示剩余耐久。

## 10.3 坐骑图标

进攻坐骑与防御坐骑分别显示在两个槽位中。

同时占据两个坐骑槽的坐骑，应当横跨两个槽位显示。

图标角标显示当前实际距离修正，例如：

```text
-2
+1
```

## 10.4 天赋图标

初始天赋和普通天赋使用不同槽位资源。

初始天赋增加锁定标记，表示：

- 不占普通天赋槽；
- 不能移除；
- 不因普通装备区失效而关闭。

## 10.5 BOSS槽

BOSS牌使用独立槽位。

BOSS图标可以显示：

- 剩余轮数；
- 专属计数；
- 专属资源；
- 当前形态；
- 是否处于静滞；
- 是否可被拆除。

## 10.6 判定区

判定区中的牌使用横向排列的小图像。

已公开的牌显示正面图像。

未公开的牌显示统一牌背。

------

# 十一、图像资源与默认图标

本游戏为图像资源驱动的卡牌游戏。

角色、武器、防具、坐骑、天赋、雕像、特殊牌、BOSS牌和状态应优先使用`asset`目录中的正式图像资源。

## 11.1 资源加载原则

客户端通过资源键加载图片，而不是在业务代码中直接写死文件路径。

例如：

```text
character.knight.portrait
weapon.snow_fox_rose_gold.icon
armor.box.icon
boss.dark_grand_knight.icon
slot.weapon.primary
```

资源清单负责把资源键映射到实际文件。

## 11.2 缺失资源处理

仅在对应正式资源不存在或加载失败时使用默认图标。

降级顺序：

```text
专属形态图像
→ 普通卡牌图像
→ 对应类别默认图标
→ 通用默认图标
```

默认图标只作为开发阶段和缺图情况下的替代，不作为最终主要视觉表现。

默认类别包括：

- 默认角色；
- 默认武器；
- 默认防具；
- 默认坐骑；
- 默认天赋；
- 默认雕像；
- 默认特殊牌；
- 默认BOSS牌；
- 默认状态；
- 默认槽位；
- 默认牌背。

图片加载失败时不得显示浏览器的破损图片标志。

------

# 十二、中央区域

中央区域只显示牌和当前正在进行的操作。

## 12.1 空闲状态

没有操作正在结算时，中央显示：

- 牌堆；
- 弃牌堆；
- 当前回合标记。

不显示历史操作文字。

## 12.2 使用卡牌

玩家使用一张卡牌时：

1. 卡牌从玩家区域移动到中央；
2. 卡牌在中央放大；
3. 显示当前使用的武器、技能或效果；
4. 绘制来源到目标的指示线；
5. 等待响应或进入结算；
6. 结算结束后，卡牌进入对应区域。

## 12.3 当前操作标题

中央顶部只显示一行简短状态，例如：

```text
精灵正在使用雪狐玫瑰金攻击圣骑士
等待圣骑士响应
正在进行判定
正在结算第3个伤害段
```

详细过程全部写入日志。

------

# 十三、对局日志

对局日志独立于中央区域。

日志记录：

- 打出的牌；
- 使用的武器；
- 发动的技能；
- 选择的目标；
- 响应结果；
- 判定结果；
- 每个伤害段；
- 铁盾减伤；
- 防具触发；
- 护盾和血量变化；
- 濒死与救援；
- 死亡与淘汰；
- 状态获得和移除；
- 阶段变化。

电脑端日志作为可折叠侧栏。

手机端日志作为抽屉。

日志可以筛选：

- 全部；
- 操作；
- 伤害；
- 系统；
- 私密。

点击日志中的角色、卡牌、装备或状态名称，可以打开对应详情。

------

# 十四、长按详情面板

以下内容全部支持长按：

- 角色；
- 技能；
- 初始天赋；
- 手牌；
- 装备；
- 判定区牌；
- 状态；
- 中央正在结算的牌；
- 弃牌堆中的公开牌；
- 日志中的牌和角色名称。

详情面板显示：

- 正式图像；
- 名称；
- 类型；
- 颜色；
- 原始效果；
- 当前效果；
- 当前状态；
- 来源；
- 剩余次数；
- 持续时间；
- 攻击方式；
- 合成路线；
- 当前受到的天赋和角色加成。

详情面板采用侧边滑出形式，不完全遮挡场面。

打开详情时，对局计时继续。

------

# 十五、武器攻击方式切换

短按自己的已装备武器图标，用于选择和切换攻击方式。

统一规则：

- 第一次短按：选中武器；
- 再次短按：切换到下一种主动攻击方式；
- 到最后一种方式后返回第一种；
- 长按：打开武器详情；
- 切换方式不消耗卡牌和攻击次数；
- 切换方式不写入公开日志。

武器图标显示当前选中的攻击方式，例如：

```text
方式Ⅰ
方式Ⅱ
```

或：

```text
1 / 2
```

切换后立即更新：

- 攻击范围；
- 合法目标；
- 目标高亮；
- 预览指示线；
- 预计伤害结构。

以下内容不能通过点击随意切换：

- 根据目标距离自动决定的距离档位；
- 当前蓄力等级；
- 攻击后自动变化的元素形态；
- 规则规定的自动形态。

这些内容只显示当前状态，不作为主动攻击方式选项。

# 十六、操作指示线

所有具有明确来源和目标的操作必须显示指示线。

指示线用于表达：

- 操作来源；
- 操作目标；
- 当前攻击；
- 多目标结算顺序；
- 拆除或获得的具体装备；
- 卡牌传递；
- 回复；
- 反弹；
- 响应；
- 合成材料流向。

## 16.1 攻击指示线

攻击指示线从武器图标或角色面板出发，指向目标角色面板。

```text
[武器图标] ━━━━━━━▶ [目标角色]
```

线旁显示：

- 当前距离；
- 武器射程；
- 攻击类型；
- 伤害结构。

例如：

```text
距离2 / 射程3
远程 1×3×2
```

## 16.2 预览线

玩家尚未确认目标时使用虚化预览线。

合法目标：

- 面板高亮；
- 显示目标环；
- 显示距离信息。

不合法目标：

- 面板变暗；
- 显示禁止标记；
- 显示具体原因。

## 16.3 正式操作线

操作被服务器接受后，预览线变为正式线。

正式线持续到当前操作结算完成。

结算结束后：

- 指示线消失；
- 当前牌离开中央区域；
- 完整结果保留在日志中。

## 16.4 多目标操作

多目标效果从来源分叉到多个目标。

每条线显示结算序号：

```text
①
②
③
```

顺序按照逆时针规则确定。

当前正在结算的指示线加粗，其余线降低亮度。

## 16.5 指向具体装备

拆除、获得或移动装备时，指示线必须指向具体装备图标，而不是只指向玩家面板。

例如：

```text
[拆除牌] ─────▶ [目标防具图标]
```

## 16.6 反弹

反弹效果显示折返指示线：

```text
攻击者 ─────▶ 目标
攻击者 ◀═════ 目标
```

原始伤害来源仍然保留。

## 16.7 牌传递

传牌效果按照逆时针显示连续移动：

```text
1号 → 2号 → 3号 → 4号 → 1号
```

每次只高亮当前正在执行的一段。

## 16.8 多段伤害

多段伤害不绘制大量重叠指示线，而在线上显示：

```text
1×3×2
```

结算时显示：

```text
第1段 / 6
第2段 / 6
……
```

# 十七、响应界面

当玩家需要响应时：

- 攻击指示线继续保留；
- 当前响应玩家面板高亮；
- 合法响应牌和装备高亮；
- 不合法选项置灰；
- 中央显示当前攻击牌和武器；
- 显示服务器倒计时。

响应按钮只显示当前合法选项，例如：

- 打出【闪】；
- 使用防具；
- 使用近战武器格挡；
- 发动技能；
- 不响应。

若使用【闪】，闪牌移动到中央并切断攻击线。

若使用近战格挡，近战武器图像移动到攻击线位置，并按照规则只抵消对应伤害段。

# 十八、装备区失效

装备区失效时：

- 装备仍保留在原槽位；
- 装备图像覆盖统一失效效果；
- 装备效果暂时关闭；
- 玩家仍可长按查看详情；
- 不视为失去装备；
- 状态结束后恢复。

初始天赋不使用普通装备区失效遮罩。

# 十九、网络联机架构

推荐采用：

- HTTPS处理登录、房间和资料；
- WebSocket或Socket.IO处理实时对局；
- PostgreSQL保存账号和对局记录；
- Redis保存房间路由、在线状态和短期重连信息；
- 服务端独立规则引擎处理所有游戏结算。

同一房间内的所有命令按顺序单线程处理。

处理流程：

```text
接收玩家命令
→ 验证玩家身份
→ 验证当前状态
→ 验证操作合法性
→ 生成规则事件
→ 依次结算
→ 更新对局状态
→ 向各玩家发送过滤后的状态
```

# 二十、断线重连

玩家进入对局后获得重连凭据。

断线时：

- 保留原座位；
- 面板显示断线状态；
- 其他玩家仍可看到其血盾和装备；
- 客户端自动尝试重连；
- 重连后恢复最新对局状态。

重连时，服务器根据事件序号决定：

- 补发缺失事件；
- 或重新发送完整快照。

标准房间建议：

- 断线后保留座位十分钟；
- 每名玩家每局第一次断线获得一次短暂停时保护；
- 之后再次断线时，对局计时继续；
- 超时后由服务器执行默认行为。

默认行为：

- 可选技能不发动；
- 响应时不响应；
- 出牌阶段自动结束；
- 强制弃牌时随机弃置；
- 必须执行的锁定效果正常执行。

# 二十一、最终视觉要求

本游戏应以正式图像资源作为主要视觉表达。

最终版本中：

- 角色使用角色立绘；
- 卡牌使用正式卡图；
- 武器、防具、坐骑和天赋使用正式图标；
- BOSS使用专属图像；
- 状态优先使用正式状态图标；
- 装备槽使用`asset`中提供的槽位图像；
- 血量条固定为红色；
- 护盾条固定为灰色；
- 默认图标只用于缺失资源或加载失败；
- 中央区域只显示当前牌和当前操作；
- 完整历史统一记录在日志；
- 所有指向性操作均显示指示线；
- 所有角色、卡牌、装备和状态均支持长按查看详情；
- 武器通过短按切换当前主动攻击方式。
